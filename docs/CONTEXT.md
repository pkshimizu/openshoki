# shoki

メニューバー／タスクバーに常駐して音声を録音する、Rust 製のデスクトップアプリ。
ウィンドウを主役にせず、常駐したまま素早く録音を開始・停止できることを狙う。

## 概要

- 形態: デスクトップアプリ（メニューバー／タスクバー常駐型）
- 言語/技術スタック: Rust。GUI は **Slint**、トレイ常駐は **tray-icon** クレート。録音まわりの
  クレート選定は未確定（録音機能のプランで決める）。
- 実行/利用方法: `cargo run` で起動し、メニューバー／タスクバーのアイコンから操作する想定。
  起動時はウィンドウを出さずトレイに常駐する。開発時は `cargo dev`（`cargo-watch` による
  自動 再ビルド＋再起動。`.cargo/config.toml` のエイリアス）でホットリロードできる。

## 構成

- 想定するプロジェクト構成（基盤プランで確定。`docs/plans/20260627-app-foundation.md`）:
  - `Cargo.toml` — クレート定義・依存（`slint` / `tray-icon`、ビルド依存 `slint-build`）。
  - `build.rs` — `slint_build::compile` で `.slint` をコンパイル。
  - `ui/` — Slint の UI 定義。ウィンドウごとに 1 ファイル（設定画面 `app-window.slint`・
    録音一覧 `library-window.slint`・文字起こし `transcription-window.slint`・議事録
    `minutes-window.slint`）で、`build.rs` が
    コンパイルするのは `app-window.slint` だけ（他はそこから再エクスポートする）。共有の
    トークンは `style.slint`、複数ウィンドウで使う自作部品は `controls.slint`。
    **複数のウィンドウへ載せる画面の中身**は、ウィンドウとは別のファイルに置く
    （モデル一覧 `model-list.slint`。#140）。
  - `src/main.rs` — エントリ。トレイ初期化と Slint イベントループ起動。
  - `src/windows/` — ウィンドウごとの配線。`main.rs` が肥大しないよう画面単位で切り出す
    （いまあるのはモデル一覧 `models.rs` だけ。設定画面・録音一覧は `main.rs` に残っている）。
  - `src/tray.rs` — トレイアイコン/メニュー構築とイベントのディスパッチ。
  - `assets/` — トレイアイコン等の素材。

## 主要な設計判断

- **`core` / `shell` の 2 層に分ける（2026-08-29 決定）**: 状態を持つ場所を 1 つにし、判断を
  副作用から引き剥がす。決定の背景と移行の段取りは
  `docs/plans/done/20260829-core-shell-layers.md` が正で、ここには**今後も効く結論だけ**を
  置く。段階 00〜02 は #187 / #188 / #189。
  - **状態は 1 つの `AppState`**。ディスクを走査した事実もジョブが進んだ事実も、同じ `Event`
    として `update` に入る。**状態を変える口は `update` だけ**なので、「メモリの記録とディスクの
    印のどちらが勝つか」という問いが書けなくなる（#175 / #176 で 2 度書いた優先順位の規則は、
    この形では不要になる）。派生（絞り込み結果など）は**同一性だけ**を持ち、行のコピーを
    持たない（#161 の再発余地が構造的に消える）。
  - **`core` は `Vec<Effect>` を返し、`shell` が実行する**。`Effect` は一発だけで、進捗や部分
    結果は「走り出した効果の出力」として `Event` で戻る。ジョブの通番は `update` の中で
    `core` が採番する（押した瞬間に状態と `Effect` を同時に決める。別々にすると #163 と同じ
    窓が開く）。
  - **向きを守るのはクレート境界**。`shoki-core` は `shoki` に依存しないので、`core` から
    ディスクを読むコードはコンパイルが通らない（いまの `transcribe::write_decision` は
    `transcript::stored_reach` を呼んでいて、これができてしまっている）。adapter が事実を
    集め、`Event` に載せて渡す。
  - **`view` は 3 つの粒度**。1 件ぶんの軽いもの（トレイ・詳細・設定・モデル一覧）は毎 tick
    組んでよい。一覧の行は `row_key`（Copy・安い）で差分を取り、変わった行だけ `view_row`
    （文字列を組む）を呼ぶ。本文は `loaded` の `(dir, generation)` が変わったときだけ。
    **変更追跡（どこが変わったかを `update` が返す形）は入れない**——フラグを立て忘れると
    古い表示が残る、つまり性能リスクが正しさリスクに変わるため。
  - **リアルタイム捕捉は輪の外**。録音スレッドはサンプルを `core` に通さず、粗い `Event`
    （開始・経過・停止）だけを戻す。
  - **移行は縦スライスで、並走させない**。フラグ切替も影実行もしない。PR 単位で切り替え、
    マージ時点では常に 1 本にする（等価性の確認は、#164〜#176 で積み上げた既存のテストを
    `update` / `view` へ移すことで足りる）。
- **用語（この 2 つは同じ機能）**: 文字起こしの結果から作る文書は、**英語 UI は
  `meeting notes`**（#127 のデザイン。トグルは `Generate meeting notes`）、**日本語は
  「議事録生成」**を正とする。`src/summarize.rs` など先に書かれたモジュールのコメントには
  「議事録要約」が残っており、そのモジュールを触るときに揃える。Library ウィンドウの
  タブ名は #128 で `Notes` へ、操作名は `Write notes` / `Regenerate notes` へ揃えた
  （内部名は `summary.md` というファイル名が正なので `summary` のまま）。
- **配色は OS の `Palette` に委ねず、shoki 固有のトークンで持つ**（#127）: アプリアイコンの
  「和紙の地・墨・朱の落款」を起点にした配色を `ui/style.slint` の `Style` に集約し、面
  （`paper` / `sheet` / `field`）・枠（`rule` / `hairline`）・文字
  （`ink` / `ink-muted` / `ink-faint`）・朱（`seal`）・状態色（`caution` / `danger` / `done`）を
  意味で名付ける。ライト/ダークの切り替えだけ `Palette.color-scheme` に従い、**個々の `.slint`
  では色を直書きしない**（片方のテーマだけ調整が漏れるため）。
  状態の色は `StatusTone`（enum）で渡し、意味→色の対応表は `Style.tone-ink` /
  `Style.tone-mark` の 1 箇所だけに置く（文言の対応表を Rust の網羅 match に置くのと同じ趣旨）。
  **標準ウィジェット（Button / CheckBox / ComboBox / SpinBox）はこのトークンに追従しない**:
  Slint の `Palette` は読み取り専用で差し替えられないため、面と文字だけが shoki の配色になり、
  操作部品は OS の見た目のまま残る。揃えるには自作コントロールが要り、そのぶんキーボード・
  フォーカス・アクセシビリティを自前で持つ必要がある（`docs/rules/slint.md`）。
  共通部品は `ui/controls.slint`（`SectionHeading` / `Card` / `CardDivider` / `CardBlock` /
  `StatusLine` / `Badge`）と、**自作の操作部品**（`ActionButton` / `Toggle` / `Stepper` /
  `Select`。`DangerButton` は `ActionButton` に役割を固定した薄い包み）。std-widgets の
  `Button` / `CheckBox` / `ComboBox` / `SpinBox` は OS の配色に従いトークンへ差し替えられない
  ため、#146 で置き換えた。キーボード・フォーカス・アクセシビリティは各部品が自前で持つ。
- **設定画面は本文をまるごとスクロールさせ、固定フッタを持たない**（#127）: タイトルバーは OS が
  描く。通信の注記・バージョンは本文の末尾にあり、一緒にスクロールする。機能ごとの設定は
  **扉**（`Door`）から専用ウィンドウへ渡す（#141）。
  最小サイズ（420x520）でもすべての設定に届く。議事録生成は独立したセクションにせず、
  Transcription の面の中に沈めた帯（左端の細い縦罫＋`NEEDS TRANSCRIPTION` のバッジ）として置き、
  従属関係を入れ子で示す。
- **常駐型を前提にする**: 通常のウィンドウアプリではなく、メニューバー／タスクバーに常駐して
  いつでも録音を始められる体験を中心に据える。UI 設計・ライフサイクルはこの前提に従う。
- **クロスプラットフォーム**: macOS のメニューバーと Windows／Linux のタスクバーの双方を
  視野に入れる。OS ごとの常駐 UI・録音 API の差異がハマりどころになりやすい。
- **GUI は Slint、トレイ常駐は tray-icon**: Slint 単体にトレイ常駐 API は無いため、
  `tray-icon` で常駐とメニューを担い、Slint でウィンドウ UI を担う。両者を winit ベースの
  Slint イベントループ上で協調させる（トレイのメニューイベントをポーリングで Slint 側へ橋渡し）。
- **頼まれていない読み取りは、退避されたファイルの実体を取り寄せない**（#178 で一覧の走査、
  #182 で検索へ広げた。**macOS だけ**——使うのが macOS 固有の
  I/O ポリシーなので、Windows の Files On-Demand や Linux のクラウドマウントでは従来どおり
  取り寄せが走る）: クラウド管理で実体が無いファイルは
  中身を読んだ瞬間に同期ダウンロードされるので、長さの見積もり（ヘッダ数バイト）が一覧を開く操作を
  止めてしまう。走査の間だけスレッドの I/O ポリシーで取り寄せを止める
  （`dataless::without_downloads`。詳細と実測はそのモジュールの doc が正）。取り寄せられない音源は
  長さ不明へ縮退する。**`stat` は取り寄せを起こさない**ので、音源・文字起こし・議事録の有無の判定は
  そのままでよい。実体が要る取り寄せは、選択時の `AudioPlayer::prepare`（別スレッド）や文字起こし
  ワーカーが従来どおり行う。
  **どちらの側かは `dataless::Fetch` で呼び出し側が明示する**（#182）: 頼まれていない読み取り
  （検索）は `Fetch::Blocked`（証が要るので囲いの外からは選べない）、ユーザーが頼んだ読み取り
  （録音を選ぶ・再生する・議事録を生成する）は `Fetch::Allowed`。読めなかった録音は黙って
  対象から外さず、件数を一覧の下と 0 件の説明に出す——「検索に出てこない＝無い」と読ませない
  ため。**拾えない退避の形もある**（プロバイダが実体を別名のプレースホルダへ置き換える運用では
  `NotFound` になり、未生成と区別が付かない。詳細は `dataless::is_not_downloaded` の doc）。
- **録音の再生はストリーミング、両音源のミックスは録音後に生成**: トレイの「Library…」から開く
  別ウィンドウ（`ui/library-window.slint`）で、保存先を走査したセッション一覧（`src/recordings.rs`。
  新しい順・日時形式でない/音源なしはスキップ）と再生（`src/player.rs`）を提供する。再生は 1 つの
  音声ファイルを `rodio` でストリーミング再生する（全 PCM を先読みしない。出力は録音の `cpal` と同じく
  メインスレッド保持）。両音源があるセッションは、録音停止後にバックグラウンドで `mic.mp3` と
  `system.mp3` をミックスした `mix.mp3` を生成し（`src/mixdown.rs`、0600）、それを再生対象にする
  （未生成なら再生不可）。単一音源セッションはその元ファイルを直接再生する。選択時に毎回デコード＋
  ミックスすると長い録音で UI が固まるため、重い処理（デコード・ミックス・再エンコード）は録音直後の
  1 回へ移す。文字起こし済みセッションは `mic.json` / `system.json` を話者ラベル付きで時刻順にマージ
  して表示し（`src/transcript.rs`。欠落・破損は縮退表示で落とさない）、セグメントのクリックでその
  開始秒へシークする。再生中は現在位置のセグメントをハイライトする（更新はウィンドウ表示中の
  再生 tick に相乗り）。**印は常に付き、スクロールで追うかどうかだけ**をプレイヤー帯の
  `Follow transcript` で切り替える（#154。読み返している場所を見失わせないため。設定には
  保存しない表示の好み）。再生バーは同じ `seek` を使うシークバーで、ドラッグ中はプレビュー表示だけを
  追従させ**離した時点で**シークする（連続シークで音を途切れさせない）。ドラッグ中は Slint の
  `scrubbing` フラグで再生 tick の進捗・時刻の上書きを止め、比率→秒の換算は Rust 側に集約する。
  再生不可・全体長不明のセッションは `seekable` を false にして表示専用のバーへ縮退する。
  再生対象を持たないセッションを選んだとき・Library ウィンドウを開いたときは `player.unload()` で
  再生対象を手放し、表示（未選択・停止・全体長不明）と再生ハンドルの状態を揃える（前のセッションの
  再生位置で新しいセッションの表示が動かないように。詳細は `AudioPlayer::unload` の doc コメント）。
  文字起こしの進行状況はワーカーの状態マップ（`TranscribeWorker` のセッションディレクトリ→
  `TranscribeState`＝状態＋使っているモデル・進捗の割合・失敗の理由。メモリのみで再起動で消える）
  を優先し、記録が無ければ JSON の有無で解決して、
  一覧の各行にドット（前/中/完了/失敗）・詳細ペインにテキストで表示する（変化した行だけ
  `set_row_data` する差分更新。ウィンドウ表示中の tick に相乗り）。失敗の状態テキストは警告色
  （`Style.danger`）で表示し、セグメントが無いときは状態ごとに**見出し・なぜ無いのか・次の操作**の
  3 段を出す（#154。対応表の正は `reading_pane::TranscriptPane::message`）。完了済みの再実行中は
  旧トランスクリプトの表示を維持する。
  **途中で失敗した文字起こしは、そこまでを残して読める**（#164）: 音源を最後まで読めなくても
  読めた範囲を文字起こしして保存し、失敗の理由に「どこまで読めたか」を載せる
  （`reading_pane::FailedSource`）。ただし**保存するのは残す価値があるときだけ**——1 件も
  認識できていない途中結果は書かず、**すでに在る文字起こしも置き換えない**（前の実行が最後まで
  読めていればそれは完成品で、音源がもう最後まで読めない以上、上書きは取り返しがつかない。
  正は `transcribe::write_decision`）。
  **セグメントがあっても、途中結果は `Show partial` を押すまで一覧を伏せる**——先に一覧が出ると、欠けていることに気づかないまま完成品として読んで
  しまう。伏せる条件は状態 `Failed` ではなく「この実行が読めるものを残したか」
  （`TranscriptPane::shows_partial`）で、前回の完成した文字起こしが残っているだけの失敗
  （モデルのロードに失敗した再実行など）では伏せない。
  **録音とどう食い違っているかは JSON に残す**（#175 / #176。`complete` と `gapped` の 2 欄で、
  読んだ直後に `reading_pane::TranscriptShortfall` へ畳む）ので、この区別は**再起動しても
  消えない**——失敗の記録がメモリのみなのは変わらないが、ディスクの印から復元する。食い違いは
  「**在る音源ごとに、読めて食い違いの無い JSON があるか**」で決める
  （`transcript::load_transcript`）——「読めた JSON がすべて揃っている」にすると、片方の JSON が
  丸ごと無いセッション（一方だけ失敗した・途中で止めた）が「揃っている」に化ける。読んだ結果は
  セグメントと同じ器（`main::LoadedTranscript`）に入れ、**読み込みを始めた時点で「分からない」へ
  戻す**（読み直しの最中に、たったいま完成した一覧を伏せないため）。状態行は
  `TranscriptPane::status_text` から出す（一覧と共用の状態 enum は食い違いを持てないので、
  そのままだと同じペインの中で状態行と空表示が食い違う）。Notes タブは「欠けた入力から書くことに
  なる」と言うが**止めはしない**（文字起こしが失敗した経路だけは #164 が止めている）。
  **一覧の行は変えない**（#175）: 一覧は「文字起こしが在るか」までしか言わない。揃っているかを
  出すには全セッションぶんの JSON を読むことになり、走査は取り寄せを止めた中で走っている
  （#178 の証）ので**そこでは読めない**。開いて確かめる、が一覧との契約。
- **食い違いは「途中で終わっている」と「中が抜けている」を分けて言う**（#176）: `decode_mp3` は
  壊れたパケットを読み飛ばして続行するので、`complete: true`（＝デコーダがストリーム終端まで
  到達した）だけでは「録音をそのまま写している」と言えない。読み飛ばしは中身が抜けるうえ、
  抜けたぶん以降のサンプルが前へ詰まって時刻もずれるため、**完成品と区別する**。ただし
  `could not be read past ◯◯` は事実と違う（最後までは読めている）ので、別の見出し・本文を
  用意した。**やり直しで直るとは言い切らない**——読み飛ばしは音源の破損でも一時的な読み取り
  失敗でも起きるので、断定するとどちらかで嘘になる。**議事録は止めない**（#175 が途中で終わった
  入力に採ったのと同じ扱い）: 止めると押した「Transcribe, then write notes」が黙って消えるうえ、
  一時的な読み取り失敗 1 件で自動議事録が丸ごと止まる。欠けた入力から書いたことは、ディスクの
  印と Notes タブの言い分が伝える（書いた議事録自体に出典を残すのは #184）。走り終わった記録
  （`TranscribeState::Done`）も食い違いを持つ——持たせないと、その記録がディスクの印より優先
  されるので走った直後だけ「Transcribed」と言ってしまう。
  詳細ペインの「Transcribe」
  ボタンで手動（再）実行でき、完了済みも上書きでやり直せる（設定 `auto_transcribe` とは独立。
  実行中の無効化は下の 2 つのゲートにまとめてある）。詳細ペインの「Delete」ボタンで選択中セッションを削除できる:
  ウィンドウ内モーダルの確認後、セッションディレクトリごと `trash` クレートで OS のゴミ箱へ移動する
  （復元可能にするため完全削除へのフォールバックはしない）。削除前に `player.unload()` で再生対象を
  手放し、成功後は一覧・メモリ・文字起こし／要約の状態マップから除去して未選択表示へ戻す
  （`clear_recordings_selection`）。失敗はログのみで縮退する。
  **議事録要約は右ペインのタブ（Transcript / Notes）で切り替えて表示する**（#81）: Notes は
  `summary.md` を行単位に出し、見出し行（`#` の連なり＋空白か行末）だけ記号を落として強調する
  （Markdown をどこまで解釈するかの正は `main::summary_rows` の doc）。読み込みは文字起こし JSON と同じガード（サイズ上限・通常ファイル確認）で、
  欠落・破損・空はいずれも状態依存の空表示に落とす（状態→文言の対応表の正は
  `reading_pane::SummaryPane::message`。ここに並べ直すと片方だけ古くなる）。文字起こしが無いセッションは
  「まだ書いていない」ではなく「まだ書けない」と言い分ける。**入力が無いときは、なぜ無いのかで
  3 つに割れる**（#165。`reading_pane::TranscriptInput`）: いま作っている（`WaitingForTranscript`）／
  作ろうとして失敗した（`TranscriptFailed`）／まだ何もしていない（`Blocked`）。`Blocked` の主操作は
  **「Transcribe, then write notes」**で、文字起こしジョブに議事録の依頼をぶら下げて投入する
  （`main::chained_summarize_job`。続けるかどうかの判断は `TranscribeWorker` が持ち、**全音源
  成功したときだけ**進む＝自動投入と同じ判断）。読める文字起こしが在れば作り直し中でも
  `Ready` 扱いで、Notes タブは「まだ書いていない」のままにする。状態の解決は文字起こしと同型（ワーカーの状態マップを優先し、
  無ければ `summary.md` の有無）で、一覧行にはインジケータを持たないぶん tick は詳細ペインの
  現在値と比べて追従させる。詳細ペインの「Write notes」ボタンで手動（再）生成でき、設定
  `auto_summarize` とは独立に走る（文字起こしが無いセッションは入力が無いので無効）。
  要約の進行状況は**キュー待ち（`Queued`）と生成中（`Summarizing`）を分ける**（#133）:
  キュー待ちの間だけ取り消せ、取り消しは Write notes ボタンと差し替えず状態行の隣に出す
  （理由は `ui/library-window.slint` の状態行のコメント）。取り消しの仕組み（状態マップの
  ジョブ通番が「いま有効なジョブ」の単一のソース）と、**走り出したジョブを止められない**理由の
  正は `SummarizeWorker::cancel` の doc。削除の可否判定と取り消しは `cancel_queued` が
  1 回のロックでまとめて行う（分けると、その隙間で走り出したジョブのセッションを消せてしまう）。
  無効化のゲートは 2 つに分ける: **`detail-files-in-use`**（文字起こし中・要約生成中＝ワーカーが
  ファイルを読み書きしている）が Delete を止め、**`detail-jobs-pending`**（それに要約のキュー
  待ちを足したもの）が Transcribe / Write notes を止める。キュー待ちはまだファイルを触って
  いないので削除でき、Rust 側が**先に取り消してから**消す（UI のゲートは tick 遅れがあるので、
  削除の直前にワーカーの状態を見て、走行中なら削除しない）。
  **文字起こし側は投入時点から `Transcribing`** で、キュー待ちの分離・取り消しは #133 では
  要約だけに入れた（対称化は未対応）。タブの選択は UI が所有し、Rust は両方の中身を
  常に最新へ更新する。
- **シークは「できなければその場で表示を進めない」縮退にする**: `AudioPlayer::seek` は失敗を `Err` で

- **アイコンは 1 つのマスターから生成し、決定的な生成物だけコミットする**: 筆の一画の**形の正は

  `scripts/check-icons.sh`（CI でも実行）が検査する。
- **メニューバーはアプリアイコンを流用せず、専用のモノクロ glyph にする**: Tahoe のアプリアイコンは
  ガラス質の squircle で、18pt に縮めると識別できない。同じ筆の一画から作ったモノクロ PNG を別資産に

  `tray.png` が 36x36 なのは、`tray-icon` の macOS 実装が表示高さを 18pt に固定するため（Retina 2x）。
- **停止後の後処理は「正規化→文字起こし投入→ミックス生成」の順で行う**: 会議アプリ
  （ブラウザ）の AGC がマイクの OS 入力ボリュームを下げ、録音が極端に小さくなることがある
  （実測ピーク -35dBFS）。停止後のバックグラウンドワーカー（`src/mixdown.rs` の
  `PostProcessWorker`）が、ピーク < -30dBFS の音源だけを目標 -3dBFS・上限 +40dB で
  ピーク正規化して上書きし（実質無音 < -70dBFS は増幅しない）、その後に文字起こしを投入して、
  続けてミックスを生成する（後段は正規化済み音声を使う）。文字起こしは音源別ファイルを入力に
  するのでミックスの完了を待たず、**両者は別スレッドで並走する**（重い ML 推論どうしの
  直列化だけを `src/inference_slot.rs` が担う）。shoki からデバイスゲインは
  操作しない（会議アプリと奪い合いになるため）。
- **多重起動を排他ロックで防ぐ**: 常駐アプリが複数プロセス同時に動くとトレイ重複・自動録音の
  二重発火・保存先の奪い合いを招くため、起動時に `config::cache_dir()` 配下のロックファイルへ
  `fs2` の `try_lock_exclusive()` で排他ロックを取る。既に別インスタンスが保持していれば英語ログを
  出して即終了する。ロックは OS がプロセス終了・クラッシュ時に自動解放するため stale lock に
  ならない。ロックを用意できない異例環境（`ProjectDirs` 取得不可等）ではガードを諦めて起動を
  続行する（起動不能にしない）。ガードは全 OS 共通（`cfg` で囲まない。`src/single_instance.rs`）。
- **アイコン素材は PNG を埋め込み RGBA へデコードして使う**: トレイのステータスアイコンと
  メニュー項目アイコン（`muda::IconMenuItem`）に使う画像は、`assets/` の PNG を `include_bytes!`
  でビルド時に埋め込み、`png` クレートで RGBA へデコードして `Icon::from_rgba` を作る。muda の
  `Icon::from_path` は Windows 専用で macOS では使えず、また `.app` の Resources パス解決に
  依存しないため、この埋め込み方式で `cargo run`／`.app` 双方に同じ素材を確実に届ける。
- **録音は cpal + mp3lame-encoder で MP3 出力**: マイク取得は `cpal`（既定入力デバイス）、
  エンコードは `mp3lame-encoder`（libmp3lame）で `.mp3` に書き出す。形式は互換性重視で MP3。
- **マイク音声とシステム音声は別ファイルに保存**: 将来の文字起こしのため、マイク（発話）と
  スピーカー等のシステム音声（再生音）は混ぜず、音源ごとに別の MP3 に保存する。1 回の録音
  セッションが音源ごとの複数ファイルを生む。
- **録音セッションはディレクトリ単位でまとめる**: 保存ディレクトリ（設定で選ぶ親）の配下に、
  セッションごとの `<日時>`（`%Y%m%d-%H%M%S`、例 `20260628-143025`）サブディレクトリを作り、
  その中に成果物を固定名で置く（マイク=`mic.mp3`、将来のシステム音声=`system.mp3`、文字起こし
  結果など）。日時はディレクトリ名が持ち、ファイル名は音源/種別を表す。セッションディレクトリの
  組み立ては録音呼び出し側で一度行い、各音源モジュールはそのディレクトリへ書き込む。
  セッションディレクトリに残った一時ファイル（`*.part.<pid>`。正規化中の音声・議事録の書き出し）は
  **Library ウィンドウを開いたときに、一覧へ出たセッションの直下だけを対象に**回収する
  （#134。範囲・時期・限界の正は `recordings::spawn_session_part_sweep` の doc）。
- **システム音声の取得は OS 依存、macOS 先行で ScreenCaptureKit**: スピーカー出力の
  ループバック取得は共通 API が無く、macOS は `screencapturekit`（ScreenCaptureKit）で行う。
  Windows（WASAPI loopback）/ Linux（monitor source）は後続。マイク録音は全 OS 共通（`cpal`）。
- **設定は OS 標準ディレクトリに TOML で永続化**: ユーザー設定（録音ファイルの保存先など）は
  `directories` で得る OS 標準の設定ディレクトリに、`serde` + `toml` で保存・復元する。
  読み込み失敗時はデフォルトへフォールバックしてアプリは落とさない。
- **登録アプリのマイク使用に連動して録音を開始・停止（macOS 14.4+, オプトイン）**:
  ユーザーが `.app` で事前登録したアプリの**マイク入力**（`kAudioProcessPropertyIsRunningInput`
  をバンドル ID で照合）を検知し、マイクを使い始めたら録音を自動開始、使い終わったら（＝通話終了）
  デバウンス後に自動停止する。
  オンラインミーティング録音が主用途。会議アプリ（ブラウザの Google Meet・Zoom.app 等）は通話中
  ずっとマイク入力を掴み、ミュートでも手放さないことが多いため、ミュート・発言の合間・長い沈黙では
  止まらず、通話終了（マイク解放）で止まる。出力（スピーカー）を合図にしないのは、ブラウザが通話に
  関係なく出力ストリームを持続保持し「出力の途絶」が起きないため。自動停止の対象は自動開始した録音
  のみ（手動開始は対象外）。既定 OFF のオプトイン。macOS 14.4 未満は無効（開始も停止も行わず手動）。
  自動録音は本経路に一本化されている（汎用のマイク使用検知による自動開始は廃止）。
- **マイクを使っているアプリの特定は公開 API だけで行う（private API は持たない）**:
  Mac App Store が private API を禁じており、配布経路でビルドを分岐させないため、GitHub 配布版でも
  private API を使わない（#107。検証は #77）。1 プロセスにつき次の 3 つを引き、**得られた ID を
  すべて集合に入れて**登録アプリと照合する（どれか 1 つに畳まない。経路によって「ヘルパー自身の
  ID」と「親アプリの ID」のどちらが得られるかが変わるため）: `kAudioProcessPropertyBundleID`
  （CoreAudio が持つ値）、`NSRunningApplication` の直接のバンドル ID、`proc_pidpath` で得た実行
  パスの**最も外側**の `.app`（`.app` は入れ子になるので内側を採らない）。
  **既知の限界**: WebKit を音声ホストに使うアプリ（Safari 等）は検知できない。マイクを掴むのが
  共有の XPC サービス（`com.apple.WebKit.GPU.xpc`）で、そこからホストアプリへ辿る公開 API が
  無いため。対象外であることを README と設定画面で伝える
  （`app_audio_monitor::auto_record_limitation`）。private API を使えば解決できるが、
  「Safari の自動録音を捨てて MAS へ進む」判断を採った（根拠は
  `docs/plans/done/20260722-mac-app-store-submission.md` の「判断の記録」）。
- **文字起こしはオンデバイス whisper で録音停止時に実行（オプトイン）**: 録音停止後、設定 ON なら
  各音源（`mic.mp3` / `system.mp3`）をローカルの whisper.cpp（`whisper-rs`）で文字起こしし、
  セグメントの開始/終了時刻付き JSON（`mic.json` / `system.json`、0600）をセッションディレクトリへ
  保存する。既定はオンデバイス（オプトインでオンライン文字起こし=OpenAI Whisper API も選択可。
  既存の JSON 契約を維持する）。MP3 は認識時に 16kHz/モノラル PCM へ
  デコードして渡す。CPU 負荷が大きいためバックグラウンドの逐次ワーカーで処理し、既定 OFF の
  オプトイン。**モデルは内蔵**: カタログ（`whisper_model::CATALOG`、Tiny〜Large v3 の 6 種・
  既定 Small）から設定画面で選び、未取得なら選択時（または初回の文字起こし時）に HTTPS で自動
  ダウンロード（SHA-256 検証・一時ファイル→リネームの原子的配置・進捗を設定画面に表示）し、
  OS 標準データディレクトリの `models/` へ保存して再利用する。**ダウンロードの仕組みは
  種別非依存の共有基盤**（`src/model_download.rs`）が持ち、`src/whisper_model.rs` は
  カタログ（どのモデルを選べるか）だけを定義する（基盤の切り出しは #79。議事録要約 LLM も
  同じ基盤に載っている。#80）。
  UI 起点とワーカー起点の取得は状態マップの check-and-set で直列化し二重取得しない
  （キーはモデル ID なので、種別をまたいで一意にすること）。
  **同時ダウンロード数の上限は持たない**（#120 の判断。根拠は `request_download` の doc）:
  直列化しても総バイトは変わらず帯域を分け合うだけで、種別をまたいで待たせると逐次ワーカーが
  無関係な取得で数十分止まる。並走で本当に困るディスクは、上限ではなく**開始前の空き容量確認**
  （必要量に並走ぶんの残りバイトも加算する）と受信サイズの上限で守る。取得を引き受けた区間は
  番人（`DownloadGuard`）で囲み、結果を記録せずに抜けても状態を `Downloading` のまま残さない
  （残すとそのモデルは二度と取得されず、空き容量の見積もりも恒久的に過大になる）。
  **同じ種別でモデルを選び直したら、前に選んでいたモデルの取得は打ち切る**（#124。
  `ModelDownloader::cancel_download`）: 打ち切りフラグを状態マップと同じロックで持ち、受信ループが
  1 チャンク（64KiB）ごとに見て抜ける。打ち切りは**失敗ではない**ので状態は `NotDownloaded` へ
  戻し（`Failed` にしない。状態行で「途中でやめた」と「落とせなかった」を混同させないため）、
  部分ファイルは `PartFile` の Drop が消す（レジュームは持たないので、戻すと全量やり直し）。
  打ち切る対象は**直前に選んでいた 1 つだけ**で、一覧の「Download」で別のモデルを
  明示的に落としている最中に選び直しただけでは巻き添えにしない。**ワーカーが必要としている
  モデルも打ち切らない**（`RequiredMark`。ジョブは投入時点のモデル ID を握っているので、設定を
  変えてもそのジョブが要るのは古いモデル。止めても取り直すかジョブが失敗するだけ）。
  打ち切り待ちの取得は**「取得中」に数えない**（`should_start_download` /
  `in_flight_remaining_bytes`）: 数えると、選び直して元へ戻したときに誰も取得を始めないまま
  終わり、他モデルの空き容量の事前確認も止まると決まっている取得のぶんまで要求する。
  打ち切りの要求は**担当の交代をまたいで届く**必要があるので、フラグ（担当ごとに作り直される）
  とは別に世代（`State::cancel_epoch`。モデル ID に紐づく）を持ち、待っていたスレッドは担当を
  引き受ける直前に世代を見て、変わっていたら取得を始めずに降りる。
  一時ファイル（`*.part.<pid>`）の命名・rename・後始末は `src/atomic_replace.rs` が持ち、
  パニックでも消す。強制終了で残ったものは mtime で判定して掃除する（モデルの保存先は起動時
  =#130。録音の保存先はセッションディレクトリ規約の項を参照=#134）。
  通信は受信のみで音声は送らない。
  **モデルは機能ごとの専用ウィンドウで管理する**（#117 で一覧と削除、#138 で取得と選択、#141 で
  文字起こし・議事録の 2 つへ分割。一覧の実体は `ui/model-list.slint` の `ModelList` で、ウィンドウは
  `ui/transcription-window.slint` / `ui/minutes-window.slint`。合成と配線は
  `src/windows/models.rs`）: **その機能のカタログ全件を並べ**（未取得も出す）、
  行から「使う（`select_model`。**選ぶ場所はここだけ**）」「取得する
  （`request_download`）」「削除する（`ModelDownloader::delete`）」を行う。`models/` にある
  カタログ外のファイルも末尾に並べて掃除できる（**種別が判定できないので両方のウィンドウに
  同じものを出す**——片方に置くと、そちらを開かない人からは消せなくなる）。走査とラッチは
  2 つの一覧で共有し、両方開いていてもディスクを見るのは 1 回だけ（`ModelLists`）。参照するカタログ集合の正は
  `model_download::REGISTERED_CATALOGS`（呼び出し側で並べ直すと、種別を足した人が片方だけ更新して
  **その種別の削除ガードが静かに外れる**）。行の状態は**取得の軸**（`ModelStatus`）と**使用の軸**
  （`windows::models::RowUsage`）に分け、操作の可否（`can_use_row` / `can_download_row` /
  `can_delete_row`）は状況が絡むので Rust の純粋関数が決める（enum から導けないものを Slint 側で
  導出させない）。行は差し替えず**変わった行だけ** `set_row_data` する（差し替えると押下・ホバーの
  状態が飛んでクリックを取りこぼす。録音一覧と同じ流儀）。
  削除は**完全削除**（録音の削除と違いゴミ箱へ入れない。理由は `delete` の doc）で、**状態マップの
  エントリも一緒に消す**（`status_of` はメモリ優先なので、消さないと設定画面が「削除したのに
  Downloaded」と表示し続ける）。削除できない条件は 2 段で守る: 取得中は**基盤側**が拒否し
  （完了時の rename で復活するため）、ジョブが読んでいる最中（文字起こし・要約。キュー待ちを含む）は
  **押された時点で再確認**する。種別の判定は登録簿の `ModelKind` で行い、表示文言
  （`ModelSpec::kind`）を判定キーにしない。`config.toml` のモデルパス上書きが `models/` 直下を
  指している場合も、その行を同じ種別として守り、**上書き中はカタログの選択が使われず消しても
  再取得されない**ことを状態と確認モーダルで伝える。
  **ディスクの走査は「開いたとき・操作の直後・取得の完了を拾った 1 回」だけ**（100ms tick に
  常時は載せない。`docs/rules/performance.md`）。取得の進捗と状態の変化は状態マップだけで分かるので、
  tick は行の組み直しだけを行い、**記録が取得済みになった ID の集合が変わったとき**に 1 回だけ
  走査し直す（`downloaded_ids` によるラッチ。「記録は取得済みだが実体が無い」を条件にすると、外部で
  消された場合などに走査が止まらない）。上書きパスの解決も走査と同じタイミングで済ませる
  （行ごと・tick ごとに `canonicalize` しない）。tick の組み直し（`ModelsRefresh::Poll`）と
  取得完了の走査し直し（`Rescan`）は**確認モーダルと通知に触らない**（触ると 100ms でモーダルが
  閉じて削除が完走できず、失敗の理由も読めない）。ただし走査に失敗したときは tick 由来でも通知で
  伝える（カタログの行は必ず並ぶので、空表示では気づけない。`refresh_cause`）。
  `config.toml` の上書きは**種別単位でも効かせる**: 上書き先が別のファイルなら、その種別の行は
  「使う」「取得する」を出さず（落としても使われない）、ジョブが走っていても「使用中」にしない
  （カタログのファイルは開かれないので、掃除できる）。上書きがその行のファイルを指すなら、
  取得は出す（落とすことが動かす唯一の手段）。
  `whisper_model_path` は上級者向けの上書き（config 手編集のみ）。**上書き中は whisper を選び直しても
  取得を始めず**、設定画面の状態行に上書きを使っている旨を出す（#123。要約 LLM と同じ扱い。条件と
  取得の契機の正は `main::model_downloads_on_select` の doc コメント）。認識言語は設定画面の
  ComboBox（カタログ `TRANSCRIBE_LANGUAGES`、主要 8 言語＋`auto`）で選び、既定は英語（`en`）。
  whisper へは常に言語コードを明示して渡す（whisper.cpp の既定が `en` のため、`auto` も
  明示しないと自動判定にならない）。
- **議事録要約は「オンデバイス LLM（既定）／オンライン LLM（オプトイン）」の選択制**:
  文字起こし結果からの要約（議事概要・議題内容・決定事項・アクションアイテム）は、既定では
  llama.cpp（`llama-cpp-2`）でローカル実行する。ユーザーが明示的に選択した場合のみ、
  オンライン LLM（Claude / OpenAI / Gemini）へ文字起こしを送信して要約できる（設定画面に
  送信警告を明示。API キーはユーザー自身のものを macOS Keychain に保存し、config には
  置かない）。ローカルモデルは whisper と同じ共有基盤（`src/model_download.rs`。初回 HTTPS
  ダウンロード・SHA-256 検証・ジョブ単位ロード）で管理し、要約言語は認識言語設定に追従する。
  生成は文字起こし完了後の自動（オプトイン・既定 OFF）と手動の両対応。
  **実装（#80）**: `src/summarize.rs` がエンジン非依存の共通部（ジョブ投入・状態管理・
  `summary.md`（0600）の保存・プロンプト組み立て・チャンク分割）を持ち、エンジン固有の実装だけを
  サブモジュールへ分ける（`src/summarize/on_device.rs`。オンラインは後続で兄弟として足す。
  分岐は `SummaryEngine` の enum ディスパッチ）。ワーカー（`SummarizeWorker`）は
  `TranscribeWorker` と同型の mpsc ＋逐次スレッドで、**`TranscribeWorker` が全音源の文字起こしに
  成功したときだけ**要約ジョブを投入する（`TranscribeJob.summarize` にぶら下げて渡す。
  部分的に失敗した文字起こしから議事録を作らないため。#164 で途中結果を残すようにしたあとも
  この判断は変えていない——読めるものが残っていても、欠けたものを入力にすれば「欠けたまま
  完成品に見える議事録」になる）。
  **ジョブの連結は投入順を決めるだけで排他にはならない**（別セッションのジョブがキューにあれば
  whisper と LLM が並走する）ので、ピークを重ねないための直列化は共有ロック
  （`src/inference_slot.rs`）が別途担う。**モデルを動かす区間だけ**排他し、モデルの
  ダウンロードはスロットの外に置く（待たせても CPU・メモリの節約にならないため）。
  設定は `auto_summarize`（既定 OFF）で、`auto_transcribe` が OFF なら要約も走らない。
  使う LLM は設定画面の ComboBox（`summary_model`）で選ぶ（#119。選択肢には所要時間とメモリの
  目安を添える）。**選択時に取得を始めるのは `auto_summarize` が ON かつ `summary_model_path`
  未設定のときだけ**にして、使わないモデルを数 GB 落とさない（条件と取得の契機の正は種別を跨いで
  `main::model_downloads_on_select` の doc コメント 1 箇所。#123 で whisper 側のパス上書きも同じ
  抑止に揃えた。whisper に `auto_summarize` に当たるゲートを置かない理由も同じ doc に書いてある）。
  要約言語は `ja` だけ専用プロンプト（見出しも日本語）で、他は英語のプロンプト骨組みに出力言語を
  指定する（`auto`・カタログ外の値は「文字起こしと同じ言語」を指示）。品質を検証済みなのは
  **日本語と英語だけ**（#78）。
  **#78 の検証で確定した実装上の前提**: `llama-cpp-2` は `whisper-rs` と同居できる
  （どちらも ggml を同梱するが CPU 構成では衝突しない。GPU 構成は未検証）。
  **`llama-cpp-2` 0.1.152 では Metal が効かない**（`libggml-metal.a` はビルドされるが
  `libggml-base.a` が登録関数を参照せずリンカに落とされ、`with_n_gpu_layers` が黙って無視される）。
  実行は CPU＋Accelerate BLAS になる。プロンプトは `n_batch`（既定 2048）以下に分けて
  `decode` へ渡す（一括だと llama.cpp が abort してプロセスごと落ちる）。生成結果は
  トークン単位で文字列化せずバイトで受けてから UTF-8 にする（日本語はマルチバイト文字が
  トークン境界をまたぐ）。サンプリングは貪欲でよい。トランスクリプトが約 4,000 トークンを
  超えたら map-reduce へ切り替える（コンテキスト長ではなく **prefill が超線形に伸びる**のが
  理由。分・文字数への換算は `summarize::CHUNK_TOKEN_BUDGET` の doc を正とする）。モデルは Qwen2.5-Instruct Q4_K_M の
  3B / 7B の 2 つをカタログに載せ、**既定は 7B**（4 分の会議で 53.5s / 8.2GB。3B は半分の時間と
  メモリだが、日本語で曜日を捏造し期限欄に雛形語が漏れた。議事録では捏造の害が取りこぼしより
  大きいという判断）。ピーク RSS は会議の長さではなく `n_ctx` で決まる（実装は 8,192 固定）。
  アクションアイテムの書式指定に**人名入りの例を置かない**（その人名が架空の担当者として
  出力に漏れる。山かっこのプレースホルダにする）。
- **プライバシー方針は「既定では外部送信しない」**: 音声・文字起こしは既定でデバイス外へ
  出ない。オンライン LLM エンジン（文字起こし=OpenAI、要約=Claude/OpenAI/Gemini。Claude は
  API が音声入力非対応のため文字起こし不可）を明示的に選択した場合のみ、選択した 1 社へ
  送信される。README・LP の文言もこの表現に統一する（「外部送信しません」と断言しない）。
- **ユーザーに見せるメッセージは英語**: GUI 文言（Slint ウィンドウ・トレイメニュー・ツール
  チップ・メニューバー）とターミナルに出るログ／エラー文言（`eprintln!` / `println!` /
  `Err(...)` / `expect` / `panic!`）は英語で書く。i18n 機構は持たずリテラルを直接英語にする。
  ソース内のコメント（doc コメント含む）と `docs/` のドキュメントは日本語のまま。この Language
  節の内部用語（日本語）は実装時に英語 UI 文言へ翻訳する（例: 「録音を開始」→ `Start Recording`）。
- **Dock 非表示は「ループ開始後に activation policy を Accessory へ」設定する**: 常駐アプリ
  として Dock・アプリスイッチャーに出さない。Slint のイベントループ（winit）は未バンドル起動
  （`cargo run`）だと `applicationDidFinishLaunching:` で activation policy を `Regular` に強制する
  ため、`main()` 冒頭で設定しても上書きされる。`slint::invoke_from_event_loop` でループ開始後に
  一度 `Accessory` を適用して維持する。バンドル済み `.app` では winit が policy を触らないため
  `Info.plist` の `LSUIElement` が効く（配布時に付与）。
- **メニューからの再表示は前面化・キー化まで行う**: `show()` は表示中のウィンドウには no-op で、
  Accessory 常駐アプリはトレイメニューのクリックでもアクティブ化されないため、他アプリに
  隠れたウィンドウが背後に残る。`show_window()` の末尾で対象の NSWindow を直接前面化・キー化し、
  アプリをアクティブ化する（詳細は `bring_to_front` の doc コメント参照。macOS 以外は no-op）。
- **配布は Mac App Store に寄せる（GitHub Releases では配らない）**: リポジトリを private に
  する方針（#112）のため、Releases も Pages も公開に使えない。一般配布は MAS 一本にする
  （#109。可否は #77 で検証済み・GO）。#20 は「`v*` タグ push で
  `aarch64-apple-darwin` の `.app` バンドルを組む」ところまでをスコープとし、**Releases への
  添付は行わない**（組んだバンドルは MAS パッケージングの土台として使う）。
  メニューバー常駐アプリなので生バイナリでなくバンドルとし、`Info.plist` に
  `LSUIElement`・`NSMicrophoneUsageDescription`・`LSMinimumSystemVersion=13.0` を持たせる。
  正式なコード署名・公証は証明書調達後に別途対応し、当面は ad-hoc 署名に留める。
- **バージョンは SemVer・`Cargo.toml` の `version` が唯一の正**: タグ（`v{version}`）・
  `Info.plist`・アプリ内表示はすべてここから導出する。リリースはバンプコミット→タグ手動
  push の順で行い、タグと `Cargo.toml` の不一致はリリース CI が fail させる（二重管理や
  bot コミットによる自動注入はしない）。アプリへの埋め込みは `env!("CARGO_PKG_VERSION")`
  （コンパイル時定数）で行い、設定画面の末尾に `shoki v0.1.0` の形で表示する（#74。
  表記の組み立ては `main.rs` の `app_version_text`）。初回リリースは `v0.1.0`、1.0.0 への
  引き上げは署名・公証や機能の安定を目安に後続で判断する。
- **アプリ紹介 LP は専用の public リポジトリで公開する**: 本体リポジトリは private にするため
  （#112）、その Pages は使えない（private リポジトリの Pages は有料プラン限定）。LP
  （#75 / #76）は別に作る public リポジトリへ置き、`site/` 配下の素の HTML/CSS
  （英語 `/`＋日本語 `/ja/` の 2 ページ、外部 CDN 依存なし）を `actions/deploy-pages` で
  公開する。ダウンロード導線は GitHub Releases ではなく App Store へ向ける
  （MAS 公開前は「ソースからビルド」の案内に留める）。
- **Apple Developer Program は加入済み。Mac App Store へ進む（Safari の自動録音は捨てる）**:
  MAS（有料）の可否は #77 で検証し、**GO** と判断した。当初は GitHub Releases との並行提供を
  前提にしていたが、リポジトリを private にする方針（#112）に伴い**配布は MAS 一本**に決めた
  （2026-07-26）。App Sandbox 下で
  CoreAudio のプロセス照会・ScreenCaptureKit・security-scoped bookmark・マイク取得はすべて動く。
  private API の公開 API 置換も Chrome / Zen / Slack / Zoom では成立する。唯一 Safari
  （WebKit 系）だけは公開 API で帰属できず現状より機能が落ちるが、影響が「Safari で会議に出る」
  構成に限られることから、**対象外と明示したうえで進める**判断を採った（2026-07-26）。
  「機能を落とさない」を当初の絶対条件にしていたので、この判断と根拠は
  `docs/plans/done/20260722-mac-app-store-submission.md` の「判断の記録」に残してある。
  加入済みのため、GitHub 配布側の Developer ID 署名・公証への引き上げも技術的には可能
  （時期は別途判断）。

## Language（用語）

このプロジェクトで意味を固定して使う言葉。実装・プラン・issue・PR でこの語を使う。

**常駐**:
アプリがウィンドウを閉じても終了せず、メニューバー／タスクバーに居続けている状態。
shoki の基本動作モード。
_避ける_: 「バックグラウンド起動」「最小化」

**録音セッション**:
録音開始から停止までの 1 回分の録音。1 つの音声ファイルに対応する単位。
_避ける_: 「レコーディング」「キャプチャ」

**core**:
純粋な層。クレート `shoki-core`。状態（`AppState`）・判断（`update` / `Effect`）・状態から
文言への表を持ち、I/O もスレッドも Slint も持たない。
_避ける_: 「芯」「コア層」「ドメイン層」

**shell**:
副作用がある層。クレート `shoki` 側の UI（Slint 配線）・job runtime・adapters。`core` が
返した `Effect` を実行し、起きた事実を `Event` で戻す。判断を持たない。
_避ける_: 「殻」「外層」「インフラ層」
