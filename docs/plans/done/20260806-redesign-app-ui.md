# アプリ全体の UI デザイン改善

- 作成日: 2026-08-06
- ステータス: 確定

## 概要

Claude の frontend-design 指針を使い、shoki の設定ウィンドウと Recordings ウィンドウを、
既存アイコンの「和紙 × 墨 ＋ 朱の落款」という固有の視覚言語で統一する。機能や Rust ⇄ Slint
の契約は維持しつつ、設定の依存関係、録音の選択・再生・文字起こし状態を一目で理解できる構造へ
再設計する。

単に装飾を増やすのではなく、常駐アプリらしい軽さと macOS の操作感を保ち、朱色を録音・現在位置・
危険操作など意味のある状態だけに使う。ライト／ダーク、空・処理中・失敗・無効・確認モーダルを含む
全状態を同じデザインシステムで成立させる。

## 背景・前提（コンテキスト）

- shoki はメニューバー常駐型の録音アプリであり、ウィンドウを主役にしない。UI は短時間で設定し、
  録音を素早く探して再生・文字起こしするための補助面である。
- GUI は Slint 1.17.0、トレイは `tray-icon`。アプリ内 UI は `ui/app-window.slint` と
  `ui/recordings-window.slint`、共有トークンは `ui/style.slint` にある。
- アプリの形の正は `assets/icon/mark.svg` の筆の一画で、アイコンは「和紙 × 墨 ＋ 朱の落款」の
  方針が確定済み。この既存資産を UI のブランド起点にする。
- ユーザー向け文言は英語、製品名は `shoki`。Rust 側のプロパティ／コールバック、保存失敗時の
  巻き戻し、シーク中のプレビュー、状態 enum 等には既存の操作契約とテストがある。
- 設定画面は 420×900、Recordings は 720×540 を基準にし、初回表示時のサイズは
  `src/main.rs` の定数と `.slint` の `min/preferred-*` を一致させる必要がある。
- 現状は Palette ベースの汎用的な角丸カード UI で、ライト／ダーク追従と機能的な階層はある。一方、
  画面固有の視覚的な焦点が弱く、設定画面は縦長で情報密度が均一、Recordings は日時・状態・主要操作の
  優先順位が弱い。既存の設定 UI 改善プランは設定画面だけを対象としていたため、今回は両ウィンドウと
  共有デザインシステムを一体で扱う。
- 現状確認用に `examples/settings_view.rs` と `examples/transcript_view.rs` があり、操作契約は
  `tests/ui_settings_rollback.rs`、`tests/ui_trigger_apps.rs`、`tests/ui_seekbar.rs` が固定している。
  この環境では macOS GUI サービスへ接続できず snapshot の取得完了までは確認できなかったため、
  見た目の最終確認は GUI が利用できるローカル環境で行う。

## 要件

- 設定・Recordings の両ウィンドウへ、shoki 固有の統一されたデザインシステムを適用する。
- 情報の優先順位、余白、タイポグラフィ、状態色、ボタン階層、空／失敗／処理中表示を再設計する。
- 設定画面では、Recording、Auto-Record、Transcription、Meeting Minutes の関係を理解しやすくし、
  従属項目を単なる opacity だけでなく構造でも示す。
- Recordings 画面では、一覧、選択中録音の概要、再生、Transcript の順に自然に視線が流れ、主要操作が
  明確になるよう再構成する。
- macOS を主対象にしつつ、Slint のクロスプラットフォーム性、既定ウィジェットの操作性、
  ライト／ダーク追従を維持する。
- ポインターだけでなくキーボードフォーカスが見え、無効状態でも内容を読めるコントラストを確保し、
  将来モーションを加える場合は reduced motion 相当の縮退経路を持たせる。
- 既存の公開プロパティ、コールバック、状態 enum、ビジネスロジック、設定値、録音データ形式、
  トレイメニューの操作内容を維持する。
- スコープ外:
  - 録音・再生・文字起こし・要約機能そのものの追加や仕様変更。
  - トレイメニューの OS ネイティブ描画の独自スキニング。メニュー項目の文言・アイコン・録音中の
    赤い tray glyph は既存方針を維持する。
  - i18n、Web UI 化、外部 UI フレームワークへの移行。
  - アプリアイコンの再設計。`mark.svg` は UI の視覚言語として再利用するが形は変更しない。

## 確定した論点

### 調査で確定した事項

1. **対象範囲**: アプリ内の全画面は設定と Recordings の 2 ウィンドウ。トレイは OS ネイティブメニューで
   独自レイアウトにできないため、既存アイコン群との色・語彙の整合確認までを対象とする。
2. **機能契約を維持する**: Slint の公開 API と Rust 側配線は既存テストに守られている。再設計はまず
   UI コンポーネント内部とレイアウトで完結させ、API 変更が必要な場合も表示専用プロパティに限定する。
3. **固有性の起点**: 新しいブランドモチーフを発明せず、既に採用済みの筆の一画、墨、朱、和紙を使う。
   暖色紙面＋セリフ体は生成 UI の定番にもなり得るが、このアプリでは名称 `shoki`、筆のマスター資産、
   朱の落款という既存決定に直接根拠がある。全面を和風装飾にせず、線・選択・状態の意味へ限定する。
4. **変更可能なサイズ**: 固定幅のままでは Meeting Minutes 追加後の設定画面が 900px と長い。
   内容を削らず、設定画面をスクロール可能な本文＋固定ヘッダ／フッタへ変えて、標準高さを縮める。
   Recordings は最小 720×540 を守りつつ、広げたときは Transcript に余白を渡す。
5. **フォント方針**: 外部フォントを同梱せず、本文・操作は OS の UI フォントを使う。日時・再生時間など
   桁揃えが意味を持つ箇所だけ等幅フォントを指定し、未搭載環境では既定フォントへフォールバックする。
   筆文字フォントを UI 全体へ使うことは可読性と配布サイズのため採らない。
6. **モーション方針**: 常駐ツールでは即応性を優先する。画面全体の登場アニメーションは入れず、
   録音／文字起こし中の状態変化や hover／press の短いフィードバックだけを検討する。

### Claude frontend-design に基づく自己批評と修正

- 初案の「和紙背景・明朝見出し・朱色カード」は、題材との関係はあるが、装飾が機能より強く、既視感の
  ある和風テーマになりやすい。そこで紙の質感画像と大きなセリフ見出しは採らず、OS 背景を保ったまま、
  墨色の階層、細い罫線、朱の意味色、筆の一画を使った選択レールへ絞る。
- カードを全項目に置く案は、現在の「均一な箱が並ぶ」問題を残すため撤回する。大きな面の区切りと
  小さな行区切りを使い分け、主要面だけに背景を与える。
- 固有のシグネチャは、`mark.svg` を大きな透かしとして飾ることではなく、筆の入りから抜けを抽象化した
  **Ink Rail** とする。選択中の録音、再生位置、アクティブな Transcript 行に同じ細いレールを使い、
  「今読んでいる場所」を一貫して示す。これを唯一の強い表現とし、他の装飾は抑える。

## デザインシステム

### カラー

`Palette` から得る OS のライト／ダーク背景を土台にし、以下を `Style` の意味トークンとして定義する。
16 進値は基準色であり、ライト／ダークとコントラスト確認後に微調整する。

- `paper`: Light `#F7F6F2` / Dark `#20201E` — ウィンドウの基底。和紙を画像で模倣せず色温度だけ使う。
- `sheet`: Light `#FFFFFF` / Dark `#2A2926` — 一覧・Transcript 等の作業面。
- `ink`: Light `#24231F` / Dark `#F2F0EA` — 主本文。
- `sumi-muted`: Light `#706D65` / Dark `#AAA69C` — 補助文・日時・状態。
- `seal`: Light `#B53A32` / Dark `#E06459` — 録音、現在位置、主要選択、危険操作の基準朱色。
- `caution`: Light `#9A6816` / Dark `#D7A84A` — WebKit 制限等の注意。失敗／破壊の朱と分ける。

状態色を生の hex で各画面へ散らさず、背景、前景、境界、hover、pressed、focus、disabled、danger、
selection、progress の意味トークンへ展開する。本文は背景に対して WCAG AA 相当、補助文と無効状態も
読めなくならない最低コントラストを目視と色計算で確認する。

### タイポグラフィ

- Display: ウィンドウ内の製品名／選択中録音タイトルのみ。OS UI フォントの 18–20px、600。
- Body: OS UI フォント 13px、通常 400／強調 600。操作ラベルは Sentence Case を基本にしつつ、
  `docs/rules/messages.md` の既存 Title Case 規約と衝突するため、実装時は規約に従い Title Case を維持する。
- Utility: 日時、経過時間、モデル容量・進捗は等幅 11–12px。数値の桁が動いてもレイアウトを揺らさない。
- セクション名は大文字化や過剰な letter-spacing で飾らず、本文より一段小さい 11–12px／600 と罫線で
  構造を示す。

### レイアウトとシグネチャ

設定画面:

```text
┌ shoki                                      v0.1.0 ┐
│ Recordings folder                                  │
│ /Users/…                              [Choose…]    │
├────────────────────────────────────────────────────┤
│ Auto-Record                              [toggle]  │
│ Start and stop with a registered call app          │
│   Delay · 4 sec      Trigger Apps · 4        [Add] │
│   Chrome      Zoom      Safari · Manual only       │
├────────────────────────────────────────────────────┤
│ Transcription                            [toggle]  │
│   Language [Japanese]   Whisper [Small]             │
│   model status / download progress                  │
│   Meeting Minutes                         [toggle]  │
│   Model [Qwen 7B] · performance note                │
└────────────────────────────────────────────────────┘
```

- 固定ヘッダに小さな筆マークと `shoki`、固定フッタにプライバシー／モデル取得注記とバージョンを置く。
- 本文は 1 つの ScrollView にし、大きなカードの連続ではなく罫線で 3 領域へ分ける。
- Auto-Record と Transcription は「名称＋一文説明＋右端トグル」の同型ヘッダにする。Slint 標準に
  Switch が無ければ CheckBox の操作契約を維持し、ラベル領域を含むクリック可能範囲とフォーカス表示を
  カスタムコンポーネントで補う。
- Meeting Minutes は Transcription の内部に無制限にインデントせず、関連を示す細いレールと余白で
  一段だけネストする。OFF 時も説明文は読める色にし、入力だけを無効化する。

Recordings 画面:

```text
┌ Recordings ────────┬───────────────────────────────┐
│ AUG 06             │  Aug 6, 2026 · 14:30          │
│ 14:30  Mic System  │  Mic + System   Transcribed   │
│ 11:10  Mic         │                 [Transcribe] ⋯│
│                    ├───────────────────────────────┤
│ AUG 05             │  [Play] ━━━━━●━━━━ 01:45/05:00│
│ 18:02  Mic System  ├───────────────────────────────┤
│                    │ ▌ Mic  01:42                   │
│                    │   Transcript text…             │
│                    │   System 01:47                 │
└────────────────────┴───────────────────────────────┘
```

- 一覧は日付と時刻を分離し、日付見出しでセッションを走査しやすくする。ただし現行 `SessionRow` には
  グループ情報がないため、まず datetime の表示分割を Slint 内で安全にできるか確認し、できなければ
  Rust の表示専用フィールド追加で行う。録音探索・選択 index の意味は変えない。
- 選択中行は全面を強いアクセント色で塗らず、`sheet` 上の薄い選択背景＋左の Ink Rail で示す。
  Transcript の現在行と同じ文法にする。
- 詳細ヘッダは日時を主見出し、音源と文字起こし状態を補助行にし、`Transcribe` は副操作、`Delete` は
  オーバーフロー相当の低強度操作へ下げる。Slint でメニュー実装が過剰なら赤い text button のまま
  右端に置く。
- Playback は独立カードをやめて詳細ヘッダ直下の transport bar にし、Play/Pause を主操作、Stop を
  副操作、時刻を等幅、進捗を Ink Rail の朱で表す。既存のシーク契約は変更しない。
- Transcript を最大の作業面にする。Speaker badge の色面積を減らし、話者・時刻を utility 行、本文を
  body 行として整える。現在行だけ Ink Rail と淡色背景で示す。
- 空状態は大きな装飾を足さず、筆マークを小さく置き、何が無いか＋次の操作を 2 行で伝える。
- 削除確認は背景を一段暗くする overlay と小さな sheet を使い、対象日時、ゴミ箱へ移ること、Cancel、
  Delete を明確にする。破壊操作だけ朱の filled button を許す。

## 実装方針

1. `ui/style.slint` を単なるフォントサイズ集から、色・文字・余白・角丸・状態の共有トークンへ拡張する。
   ライト／ダーク判定を Slint の Palette で吸収できる範囲を確認し、固定色は `seal`、`caution` 等の
   ブランド／意味色に限定する。
2. 小さな共有部品を `ui/` 内に切り出す。候補は `SectionHeader`、`SettingRow`、`StatusDot`、
   `SourceBadge`、`InkRail`、`TransportButton`、`DangerButton`。公開 API を持つウィンドウは現行の
   `app-window.slint` エントリから再 export する。
3. 設定画面を固定ヘッダ／スクロール本文／固定フッタへ再構成する。既存の `<=>` 束縛、保存失敗時の
   Rust 書き戻し、単一 `enabled-gate` はそのまま維持する。
4. Recordings の二ペインと状態モデルを維持したまま、一覧行、詳細ヘッダ、transport bar、Transcript、
   モーダルを新しい視覚階層へ置き換える。長いセグメント一覧は引き続き `ListView` で仮想化する。
5. 新しい視覚状態に必要な値が既存プロパティから導出できない場合だけ、表示専用 struct field／enum／
   property を追加する。状態 enum から導出できる bool は増やさず、状態→文言は Rust の網羅 `match` に置く。
6. 見た目の確認用 example を状態マトリクスに対応させる。snapshot はリポジトリへ固定せず、必要なら
   `/tmp` へ生成し、ライト／ダーク双方を実機で比較する。

## 実装ステップ

1. **現状基準を固定する**: GUI 利用可能な環境で設定と Recordings の current snapshot を取得する。
   420×900、720×540、Recordings の拡大状態について、通常／無効／空／処理中／失敗／モーダルを記録し、
   クリップ、コントラスト、操作階層の課題をチェックリスト化できたら完了。
2. **共有トークンを実装する**: `ui/style.slint` に paper/sheet/ink/sumi/seal/caution と文字・境界・
   focus・disabled の意味トークンを追加し、既存の直書きされた繰り返し値を置換する。両テーマで本文、
   補助文、選択、失敗、無効が判別でき、`cargo build` が通れば完了。
3. **共通部品を整える**: Ink Rail、状態表示、セクションヘッダ、ボタン階層を小コンポーネントとして
   実装する。hover／pressed／disabled／focus の全状態を確認し、TouchArea を使う部品は左クリック、
   cancel、キーボード操作と accessible label を満たせば完了。
4. **設定画面を再構成する**: 固定ヘッダ、スクロール本文、固定フッタと 3 領域へ組み替え、Meeting
   Minutes の従属関係、モデル説明、ダウンロード状態、Trigger Apps の長い注記を整理する。全入力で
   `<=>` と保存失敗時の巻き戻しが保たれ、最小高さでも全内容へ到達できれば完了。
5. **設定画面のサイズを調整する**: 実測した標準高さへ `AppWindow` と `src/main.rs::WINDOW_HEIGHT` を
   同時に変更する。初回表示、スクロール、フォルダ選択後の長いパス、0／多数の Trigger Apps、最長の
   モデル文言でレイアウトが潰れなければ完了。
6. **録音一覧を再設計する**: SessionRow を Ink Rail 選択、読みやすい日時、音源、状態へ変更する。
   必要なら表示用の日付／時刻 field を `SessionRow` と Rust の変換処理へ追加し、選択 index、差分更新、
   空一覧、数百件時のスクロール性能が維持されれば完了。
7. **録音詳細を再設計する**: 詳細ヘッダ、transport bar、Transcript 作業面、空／処理中／失敗状態を
   実装する。Play/Pause/Stop、クリック／ドラッグシーク、セグメントシーク、Transcribe、Delete の
   callback と有効条件が現状どおりなら完了。
8. **削除確認を仕上げる**: overlay、対象の説明、Cancel、Delete の視覚階層とフォーカス順を整える。
   Confirm 中の背面操作を遮断し、文字起こし中は開けず、Delete は一度だけ通知されれば完了。
9. **状態マトリクスを目視検証する**: `examples/settings_view.rs` と `examples/transcript_view.rs` を
   必要なフラグ／snapshot 出力に対応させ、ライト／ダーク、標準／最小／拡大、通常／空／無効／処理中／
   失敗／モーダルを比較する。装飾を 1 つ減らす最終レビューを行い、Ink Rail 以外に不要な強い表現が
   残っていなければ完了。
10. **操作と回帰を検証する**: 既存 UI テストを更新し、カスタム部品のキーボード／フォーカス／モーダル
    遮断テストを追加する。`cargo fmt --check`、`cargo build`、`cargo clippy --all-targets -- -D warnings`、
    `cargo test`、アイコン整合検査を通し、実機でトレイから各ウィンドウを再表示してサイズと前面化が
    保たれることを確認する。

## 影響範囲・リスク

- 影響を受けるファイル／モジュール:
  - 主変更: `ui/style.slint`、`ui/app-window.slint`、`ui/recordings-window.slint`。
  - 部品分割時に追加: `ui/components/*.slint` 相当。実際の配置は Slint import の簡潔さを見て決める。
  - 表示用データ／サイズ変更時: `src/main.rs`、`src/recordings.rs`。
  - 目視確認: `examples/settings_view.rs`、`examples/transcript_view.rs`。
  - 操作回帰: `tests/ui_settings_rollback.rs`、`tests/ui_trigger_apps.rs`、`tests/ui_seekbar.rs`、
    必要に応じて新規 UI テスト。
- リスクと対策:
  - **Slint Palette と固定色の不整合**: 全面固定配色にせず OS Palette を土台にし、意味色のみ固定する。
    実描画でライト／ダーク双方のコントラストを確認する。
  - **カスタム操作部品のアクセシビリティ低下**: 見た目だけの custom Button/Switch を乱造しない。
    std-widgets を優先し、TouchArea が必要な部品は focus、accessible role/label、keyboard、cancel を
    操作テストで固定する。
  - **設定画面のスクロール化による操作の見落とし**: ヘッダと各セクションの説明で現在位置を示し、
    主要トグルを各領域の先頭に置く。狭い高さでも末尾へ到達できることを確認する。
  - **Recordings 一覧のデータ契約変更**: datetime の分割は表示用 field の追加だけにし、セッション探索順、
    index、選択、ワーカー状態キーへ影響させない。
  - **シーク／差分更新の退行**: SeekBar の state machine、`scrubbing` 中の tick 抑止、ListView 仮想化、
    `set_row_data` の差分更新は維持し、既存テストを先に通したまま段階的に移植する。
  - **固定サイズの不一致**: `.slint` と `src/main.rs` の定数を同じ変更単位で更新し、初回 show とユーザーの
    リサイズ保持を実機確認する。
  - **視覚表現の過剰化**: 筆マーク、朱色、角丸、影を同時に強調しない。シグネチャは Ink Rail 1 つに絞り、
    朱色の面積を状態・現在位置・破壊操作に限定する。

## 未確定事項

- `Palette` からライト／ダークを判定して paper/sheet の厳密な色を切り替えられるかは Slint 1.17 の
  実装確認が必要。難しい場合は背景を Palette に任せ、固定 hex は `seal` と `caution` のみに縮退する。
- カスタム Switch を作るか CheckBox を視覚調整するかは、キーボード／アクセシビリティを含む試作比較で
  決める。操作品質が同等でなければ CheckBox を採用する。
- 設定画面の最終標準高さと Recordings の左ペイン幅は、最長文言とライト／ダークの snapshot 比較後に
  決める。Rust 側定数と同時に確定する。
- 日付グループ見出しは既存モデルで自然に実装できる場合だけ採用する。モデルを複雑にする場合は、日時を
  2 行へ分ける改善に留める。
- Slint で OS の reduced motion 設定を取得できない場合は、初回実装では継続アニメーションを入れず、
  press／hover の即時状態変化だけにする。
