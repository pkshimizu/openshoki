# 録音一覧から録音データを削除できるようにする

- 作成日: 2026-07-21
- ステータス: ドラフト

## 概要

Recordings ウィンドウの録音一覧から、選択中の録音セッションを削除できるようにする。録音は
復元不能な機微データなので、**OS のゴミ箱への移動**（復元可能）と**確認ダイアログ**で
誤削除から守る。不要な録音を溜め込まずに整理できるようにするのが狙い。

## 背景・前提（コンテキスト）

- Recordings ウィンドウ（#53 マージ済み・#54 が PR #65 で進行中）は、左に一覧
  （`SessionRow` の Slint モデル、`selected-index`）、右に選択セッションの詳細
  （日時・音源サマリー・トランスクリプト・再生コントロール）を表示する。
- **録音セッション**はディレクトリ単位（`<保存先>/<日時>/` に `mic.mp3` / `system.mp3` /
  `mix.mp3` / `mic.json` / `system.json`）。削除の単位もこのディレクトリごと。
- `src/recordings.rs` の `list_sessions` が一覧を走査し、`main.rs` が
  `Rc<RefCell<Vec<RecordingSession>>>` を保持して選択インデックスからセッションを解決する。
- 再生は `src/player.rs`（rodio・ストリーミング）。`load(path)` で対象を差し替え、`stop()` は
  対象パスを保持したまま頭出しする。**対象を手放す（アンロード）API はまだ無い**。
- `rfd` は既存依存で、`MessageDialog`（ネイティブの確認ダイアログ、同期 API）を持つ
  （ファイル/フォルダ選択で使用中の 0.17 に含まれることを確認済み）。
- ゴミ箱移動はクロスプラットフォームの `trash` クレート（5.2.6）で行える（新規依存）。
- バックグラウンドワーカー（文字起こし `transcribe.rs`・ミックス `mixdown.rs`）は、停止直後の
  セッションディレクトリへ後からファイルを書く。削除と競合しうるが、両者とも失敗をログして
  スキップする縮退設計になっている。

## 要件

- Recordings ウィンドウの詳細ペイン（右側）に「Delete」ボタンを置き、選択中のセッションを
  削除できる。
- 押下時にネイティブの確認ダイアログを表示し、承認されたときだけ削除する。
- 削除は**セッションディレクトリごと OS のゴミ箱へ移動**する（完全削除しない。ユーザーは
  ゴミ箱から復元できる）。
- 削除対象を再生準備・再生中だった場合は、再生を停止して対象を手放してから削除する。
- 削除後は一覧から当該行が消え、選択は解除される（詳細ペインは未選択表示へ）。
- 失敗（ゴミ箱移動不可など）はログを残し、アプリ・一覧表示は壊さない。
- スコープ外:
  - 複数選択・一括削除。
  - ゴミ箱を使わない完全削除オプション。
  - ファイル単位（音源別）の削除。
  - 録音中セッションの削除（録音中のセッションはまだ一覧に出ない前提。停止後に一覧へ載る）。

## 確定した論点

ユーザー確認で決定:

1. **削除方式はゴミ箱へ移動**（`trash` クレート）。録音は復元不能な機微データのため、
   誤削除しても取り戻せる方式にする。
2. **確認ダイアログあり**（`rfd::MessageDialog`、既存依存）。
3. **ボタンは詳細ペイン（右側）**。選択中セッションへの操作として対象が明確で、一覧の
   誤クリックも避けられる。

調査で確定:

4. `rfd 0.17`（既存依存）に `MessageDialog` / `MessageButtons` / `MessageDialogResult` が
   あり、追加依存は `trash` のみで済む。
5. `player.rs` は `stop()` 後も対象パスを保持する（`play_pause` で頭から再生できる設計）。
   削除時に対象を確実に手放すため **`unload()`（キューを空にし `path`/`duration` を `None` に
   戻す）を追加**する。`load()` 冒頭のリセットと同じ処理なので共通化できる。
6. 削除とワーカー（文字起こし・ミックス）の競合は、既存の「失敗をログしてスキップ」縮退で
   吸収される（ディレクトリ消失後の書き込みは失敗ログになるだけ。ゴミ箱へ移った後に書き込みが
   成功して「ゴミ箱内に新ファイル」になる窓は理論上あるが、復元時に余分なファイルが付く程度で
   実害はない）。

## 実装方針

- **`Cargo.toml`**: `trash` を追加。
- **`src/player.rs`**: `unload()` を追加（`clear` ＋ `path = None` ＋ `duration = None`。
  `load()` 冒頭と共通化）。削除経路から呼び、削除済みファイルを `play_pause` の
  「頭から積み直し」が開き直さないようにする。
- **`ui/recordings-window.slint`**:
  - 詳細ペインに「Delete」ボタンを追加（`has-selection` のときだけ表示される領域内）。
    再生コントロールと同列ではなく、誤操作しにくい位置（詳細ヘッダの右端など。実装時に
    カンプ相当の見た目で調整）。
  - `callback delete-session(int)`（選択インデックスを渡す。既存 `select-session` と同型）。
  - プロパティ/コールバックのグルーピング（プロパティ群→コールバック群）を保つ
    （`docs/rules/slint.md`）。
- **`src/main.rs`**:
  - `on_delete_session`: インデックス→セッション解決（既存 `on_select_session` と同じ検証）→
    `rfd::MessageDialog`（`Move this recording to the Trash?`、OkCancel/YesNo）→ 承認なら:
    1. `player.unload()`（再生停止＋対象解放）
    2. `trash::delete(&session.dir)`
    3. 成功: `sessions` から除去し、Slint の一覧モデルを更新（行削除）。
       `selected-index = -1`・`has_selection = false`・再生表示の初期化
       （`open_recordings_window` の初期化処理と重複するので、選択・再生表示の初期化を
       小関数へ切り出して共用する）。
    4. 失敗: `eprintln!`（`Skipping the deletion because moving the recording to the Trash
       failed: {err}` 相当。messages.md の 1 文構造・英語）。UI 状態は変えない。
  - 削除はメインスレッドの同期処理でよい（ゴミ箱移動は rename 相当で軽く、確認ダイアログを
    挟むため体感の引っかかりにならない。重くなる兆候があればワーカー化を検討）。
- **文言**（`docs/rules/messages.md`: 英語・Title Case・機微情報を出さない）:
  - ボタン: `Delete`
  - 確認: タイトル `Delete Recording` / 本文
    `Move this recording to the Trash? You can restore it from the Trash.`（パスは出さない。
    対象は詳細ペインの日時表示で特定できる）
- **README / CONTEXT.md**: Recordings ウィンドウの機能記述に削除（ゴミ箱移動）を同期する。

## 実装ステップ

1. **`player.unload()`**: `load` 冒頭のリセットと共通化して追加。ユニットテストは
   既存 player のテスト方針に合わせる（実デバイス依存のためスモークがあれば追従）。
2. **削除の中核**: `trash` 依存追加。`main.rs` に `on_delete_session`（解決→確認→unload→
   ゴミ箱移動→一覧/選択状態の更新）。一覧・選択初期化の小関数化。
   - 検証: `cargo build` / 手元で削除→ゴミ箱に入る→一覧から消える→選択解除される。
3. **UI**: `recordings-window.slint` に Delete ボタンと `delete-session` コールバックを追加。
   宣言グルーピング維持。レイアウト崩れがないか確認。
4. **異常系**: ゴミ箱移動失敗（例: 既に手で消したディレクトリ）でログのみ・アプリ継続を確認。
   削除後に `play_pause` を押しても何も起きない（`unload` 済み）ことを確認。
5. **ドキュメント同期**: README（Recordings の機能一覧）・docs/CONTEXT.md（設計判断の追記は
   「削除はゴミ箱移動」の一行程度）を更新。
6. **仕上げ**: `cargo fmt --check` / `cargo clippy --all-targets -- -D warnings` / `cargo test`。
   実機で 削除の一連（確認キャンセル含む）を確認。

## 影響範囲・リスク

- **影響を受けるファイル/モジュール**:
  - 変更: `src/main.rs`（削除コールバック・状態初期化の共通化）、`src/player.rs`（`unload`）、
    `ui/recordings-window.slint`（ボタン・コールバック）、`Cargo.toml`（`trash`）。
    README・docs/CONTEXT.md。
  - 変更なし: `src/recordings.rs`（走査ロジックはそのまま。一覧更新はメモリ上の Vec と
    Slint モデルの行削除で行い、再走査しない）。
- **リスクと対策**:
  - **再生中ファイルの削除**: rodio が開いているファイルをゴミ箱へ移動しても Unix では
    動作し続けるが、状態の食い違いを避けるため削除前に必ず `unload()` する。
  - **ワーカーとの競合**: 停止直後のセッションを即削除すると、ミックス生成・文字起こしの
    書き込みが失敗ログになる（縮退動作として許容。リスクとして PR に明記）。
  - **`trash` クレートの環境差**: macOS は Finder のゴミ箱へ、Linux は freedesktop Trash 仕様。
    失敗時はログのみでアプリ継続（完全削除への自動フォールバックはしない — ユーザーの
    「復元できる」期待を裏切らない）。
  - **インデックスのずれ**: 行削除後の `sessions` と Slint モデルの整合。除去は両方に同時に
    行い、選択は必ず解除する（ずれた選択で別セッションを誤削除しない）。
  - **確認ダイアログのブロッキング**: `rfd::MessageDialog` は同期でメインスレッドを
    ブロックするが、既存のフォルダ/ファイル選択ダイアログと同じ振る舞いで問題ない。
- **依存**: #54（PR #65: トランスクリプト表示）が同じウィンドウ・配線を触っているため、
  **PR #65 のマージ後に着手**する（コンフリクト回避）。
