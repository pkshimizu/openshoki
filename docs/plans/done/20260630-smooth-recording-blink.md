# 録音中アイコンの点滅を滑らかなグラデーションにする

- 作成日: 2026-06-30
- ステータス: ドラフト

## 概要

録音中のメニューバーアイコンの点滅を、現状の 2 段階トグル（明るい赤／暗い赤の切り替え）から、
明度をサイン波で連続的に上下させる滑らかな明滅（breathing）に変える。録音中であることを
より自然に、目に優しく示すのが狙い。

## 背景・前提（コンテキスト）

- 録音中はメニューバーのトレイアイコンを点滅させ、経過時間も表示している（issue #12 実装、
  #15 マージ済み。`src/tray.rs` / `src/main.rs`）。
- 現状の点滅は 2 値: `DotColor { Idle, Recording, RecordingDim }` を持ち、`main.rs` のタイマーが
  `BLINK_PERIOD_TICKS`(6 tick ≈ 600ms) ごとに `blink_on`(bool) をトグルして、`render_recording`
  が `Recording`（明 `#D0211C`）/ `RecordingDim`（暗 `#6A1410`）を切り替える。
- タイマーは `MENU_POLL_INTERVAL`(100ms) のポーリングに相乗りし、表示が変わるとき
  （秒の更新 or 点滅トグル）だけ `set_icon`/`set_title` を呼んで間引いている
  （`last_rendered_secs` / `last_blink_on`）。
- アイコンは `dot_icon` が 32×32 の RGBA を都度生成する（録音中の点滅でも毎回生成しており軽い）。
- 「点滅で消えたように見せない」ため透明にはせず減光に留める方針（既存コメント）。

## 要件

- 録音中アイコンの赤を、明るい赤⇄暗い赤の間で**連続的に（多段階で）滑らかに**明滅させる。
- 1 サイクル（明→暗→明）は約 2 秒。サイン波でゆったり変化させる。
- 透明度は使わず、明度（色の濃淡）で表現する（背景に依らず常に視認でき、消えたように
  見せない既存方針を踏襲）。
- 経過時間テキスト・待機表示（グレー復帰）・停止時のクリアなど、点滅以外の挙動は変えない。
- スコープ外:
  - アイコンの形・サイズ・色相そのものの変更（赤の濃淡フェードに限る）。
  - 経過時間の書式やツールチップ文言の変更。
  - Windows / Linux 固有の見え方の最適化（アイコン色を主表示にする方針は共通）。

## 確定した論点

ユーザー確認で決定:

1. **スタイル**: 赤の明度をサイン波で滑らかに明滅（breathing）。アルファ（透明度）は使わず、
   暗い赤↔明るい赤を補間する。
2. **周期**: 1 サイクル約 2 秒。

調査で確定した実装方針の前提:
- 現状の 2 値トグル（`blink_on` / `RecordingDim`）を、`0.0`〜`1.0` の明度レベルに置き換える。
- 位相はティック数ではなく**録音経過時間**（`Recorder::elapsed()`）から計算する。tick の揺れに
  依存せず時間基準で滑らかになり、既存の `elapsed` をそのまま使える。
- アイコンは滑らかさのため**毎ティック（≈100ms, 約 10fps）更新**する。32×32 RGBA 生成は軽い。
  経過時間テキスト（`set_title`）は従来どおり秒が変わったときだけ更新する。

## 実装方針

- **`src/tray.rs`: 明度パラメータでアイコンを生成するように変更**する。
  - `DotColor` の `Recording` / `RecordingDim` の 2 値を、明度レベル `level: f32`(0.0=暗,1.0=明) に
    よる補間へ置き換える。`RECORDING_BRIGHT`(#D0211C) と `RECORDING_DIM`(#6A1410) を端点として
    チャンネルごとに線形補間（lerp）した RGB でドットを描く。
  - ドット描画（円を塗る共通処理）は色を引数に取る形に切り出し、`Idle`（グレー）と録音中
    （補間色）で共有する。
  - 録音中アイコン更新の API を `set_recording_icon(icon, level)`（アイコンのみ）に整理し、
    経過時間テキストの更新（`set_title`）は別関数 or 既存の per-second 更新に残す。`set_idle` は
    現状どおり（停止時のグレー復帰・テキストクリア）。
- **`src/main.rs`: タイマー駆動を明度ベースに変更**する。
  - `BLINK_PERIOD_TICKS` / `blink_on` / `last_blink_on` を廃し、録音中は毎ティックで
    `level = breathing_level(elapsed, BLINK_CYCLE)` を計算してアイコンを更新する。
    `BLINK_CYCLE`(≈2 秒) を定数化する。
  - `breathing_level(elapsed, cycle)` は `((2π · elapsed / cycle).sin() + 1) / 2` で 0.0〜1.0 を返す
    純粋関数（I/O 無し）。`tray.rs` か `main.rs` に置く。
  - 経過時間テキストは `last_rendered_secs` の throttle を残し、秒が変わったときだけ更新する。
  - 録音→待機の遷移時に `set_idle` へ戻す既存ロジック（`was_recording`）はそのまま。
- 負荷が気になる場合の任意最適化として、`level` を数段階に量子化して前回と同じ段階なら
  `set_icon` を省く throttle を入れてもよい（必須ではない。10fps の RGBA 生成は軽微）。

## 実装ステップ

1. **`tray.rs` の色生成を明度補間へ変更**: ドット描画を色引数で共通化し、録音中は
   `RECORDING_DIM`↔`RECORDING_BRIGHT` を `level` で lerp。録音中アイコン更新 API を整える。
   `cargo build` が通ることを確認。
2. **`main.rs` のタイマーを明度ベースに変更**: `breathing_level` を実装し、`BLINK_CYCLE` を定数化、
   毎ティックでアイコン更新・テキストは秒単位 throttle。旧 `BLINK_PERIOD_TICKS`/`blink_on` 系を
   除去。`cargo build` / `cargo clippy --all-targets -- -D warnings` / `cargo fmt --check` を確認。
3. **単体テスト**: `breathing_level` の境界（位相 0 で 0.5、1/4 周期で 1.0、1/2 周期で 0.5、
   3/4 周期で 0.0 付近）を検証するテストを追加（既存 `format_elapsed` テストと同じ要領、I/O 無し）。
   `cargo test` を確認。
4. **目視確認**: 録音を開始し、メニューバーの赤ドットが約 2 秒周期で滑らかに明滅すること、
   経過時間表示・停止時のグレー復帰が従来どおりであることを確認する（`docs/rules/slint.md` の
   検証手順に準じ、必要なら確認用バイナリ＋スクリーンショット）。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - 変更: `src/tray.rs`（`DotColor` の扱い・ドット生成・録音中アイコン更新 API）、
    `src/main.rs`（タイマーの点滅ロジック・定数）。
  - `src/recorder.rs` は変更なし（`elapsed()` をそのまま利用）。
- リスクと対策:
  - **更新頻度による負荷**: 毎ティック（10fps）で 32×32 RGBA を生成・`set_icon`。軽微だが、
    気になれば `level` 量子化で間引く。録音中のみで待機時は更新しない。
  - **滑らかさの体感**: 10fps では粗く感じる可能性。まず 100ms で実装し、粗ければ
    `MENU_POLL_INTERVAL` とは別の更新間隔を検討（ただしポーリング相乗りの単純さは失う）。
  - **見た目の確認が必要**: 明滅の速さ・濃淡幅は実機で目視調整する（端点色・周期は定数化して
    調整しやすくする）。

## 未確定事項

- 明滅の濃淡幅（`RECORDING_DIM` をどこまで暗くするか）は実機の見え方で微調整の余地。
