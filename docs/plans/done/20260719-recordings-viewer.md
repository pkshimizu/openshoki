# 録音した音声一覧ビュー（再生・文字起こし表示・秒数スキップ）

- 作成日: 2026-07-19
- ステータス: ドラフト

## 概要

録音済みの音声を、アプリ（トレイ常駐）から一覧・再生・確認できるようにする。トレイメニューから
開く専用の「Recordings」ウィンドウで、録音セッションの一覧、選択したセッションの再生、
文字起こし結果の表示、文字起こしセグメントをクリックしてその発話の秒数へ再生位置をスキップ、
を提供する。録音した内容を後から振り返る導線がまだ無いため、これを一次サーフェスとして足す。

## 背景・前提（コンテキスト）

- openshoki は**常駐**アプリ（メニューバー／タスクバー）。UI は Slint、トレイは tray-icon、
  イベントループは `run_event_loop_until_quit()`。ウィンドウはトレイメニューから開く。
- **録音セッション**は保存先ディレクトリ配下の `<日時>`（`%Y%m%d-%H%M%S`、例 `20260628-143025`）
  サブディレクトリにまとまり、音源ごとに固定名で置かれる: マイク＝`mic.mp3`、システム音声＝
  `system.mp3`（macOS のみ）。保存先は設定 `recording_dir`（`Config`）。
- 文字起こしは CONTEXT の設計上、各音源をローカル whisper で処理し、セグメントの開始/終了時刻付き
  JSON（`mic.json` / `system.json`、パーミッション 0600）を同じセッションディレクトリへ保存する。
- 現状の未実装事項（調査で確認）:
  - **文字起こし生成は未実装**。issue #30（whisper.cpp で録音停止時に JSON 保存）・#31（設定 UI）が
    open。`mic.json` / `system.json` はまだ生成されない。
  - **音声再生は未実装**。依存に再生クレート（`rodio` 等）は無く、`cpal` は録音（capture）専用。
- 既存のスレッド/エラー方針: 録音は writer スレッド＋チャネルで実装（`recorder.rs`）。
  `docs/rules/error-handling.md`（握りつぶさない・永続化成功後に反映・poison 耐性）、
  `docs/rules/slint.md`（ループ稼働後の初回 show はジオメトリ明示・in-out は保存失敗時に戻す）、
  `docs/rules/messages.md`（ユーザー向け文言は英語）に従う。

## 要件

- トレイメニューに「Recordings…」を追加し、録音一覧ウィンドウを開ける。
- 録音セッションの一覧を表示する（`recording_dir` を走査、新しい順）。各項目は日時と、
  含まれる音源（mic / system）・文字起こしの有無が分かる。
- 一覧から選んだセッションの音声を再生できる（Play / Pause / Stop、経過/全体時間の表示）。
  - mic と system の両方がある場合は**両方を同時に再生**する（ミックスした単一タイムライン）。
- 選んだセッションの文字起こし結果を表示する（セグメント単位のテキスト）。
- 文字起こしセグメントをクリックすると、そのセグメントの開始秒へ再生位置をスキップする。
- スコープ外（v1 では扱わない）:
  - **文字起こしの生成そのもの**（whisper 実行・JSON 保存）は issue #30 の担当。本ビューは
    生成済み JSON を**読むだけ**。本プランは #30 の完了を前提に着手する。
  - ドラッグ可能なシークバー（プログレスバーでの任意位置シーク）は v2。
  - 録音の削除・リネーム・エクスポート・共有。
  - Windows / Linux のシステム音声（`system.mp3` はそれ自体が後続 #23/#24）。

## 確定した論点

ユーザー確認と調査で決めた事項:

1. **文字起こし依存の順序**: **#30 を先に実装**してから本ビューに着手する（ユーザー選択）。
   本ビューの文字起こし表示・秒数スキップは `mic.json` / `system.json` に依存するため、
   #30（生成）を前提とする。#30 が定める JSON スキーマは本ビューが読む契約になるので、下記
   「文字起こし JSON スキーマ（#30 との契約）」を #30 実装時に満たすこと。
2. **UI サーフェス**: 設定とは別の**新規「Recordings」ウィンドウ**をトレイメニューから開く
   （ユーザー選択）。小さい設定ウィンドウと役割を分ける。
3. **音源の扱い（再生）**: mic と system を**同時再生（ミックス）**する（ユーザー選択）。
   実装は「両ファイルをデコードして PCM をミックスした**単一の再生ソース**」を作り、1 つの
   タイムラインで再生・シークする。両音源はセッション開始起点で時間軸が共通なので、文字起こし
   セグメントの秒数はミックス済みタイムラインへそのまま対応でき、秒数スキップが素直になる。
   片方のみ存在するセッションはそのソースを単独再生する。
   - 代替案（採らない/将来）: 停止時に `mix.mp3` を生成して保存し再生。単純だが再エンコードと
     保存物が増える。エクスポート用途が出たら再検討（v1 はオンザフライのメモリ内ミックス）。
4. **音源の扱い（文字起こし）**: 文字起こしは音源ごと（`mic.json` / `system.json`）だが、再生が
   ミックスの単一タイムラインなので、表示も**両音源のセグメントを時刻順にマージした 1 本の
   トランスクリプト**にする（各セグメントに話者＝mic/system のラベルを付す）。クリックは
   セグメント開始秒への単一タイムラインのシーク。
5. **再生コントロール（v1）**: Play / Pause / Stop、経過/全体時間の表示、セグメントクリックで
   その秒へスキップ。ドラッグ式シークバーは v2。
6. **再生ライブラリ**: `rodio`（mp3 デコードは symphonia、`Sink` で再生、`try_seek` でシーク）。
   `cpal`（録音）と共存可能（rodio は内部で cpal を使う）。出力再生は特別な OS 権限を要さない。

## 実装方針

- **再生モジュール `src/player.rs` を新設**。音声出力は専用スレッド（rodio の `OutputStream` /
  `Sink`）で持ち、Slint メインスレッドからは薄い制御ハンドル（`load(source)` / `play` /
  `pause` / `stop` / `seek(secs)` / `position()` / `duration()`）で操作する。`!Send` や
  デバイス保持の都合はハンドル内に閉じ込め、録音（`recorder.rs`）のスレッド/チャネル方針に倣う。
  - 再生ソースは「デコード済み PCM をミックスした**シーク可能なメモリ内ソース**」。mic/system の
    サンプルレート・チャンネルが違う場合は共通レートへリサンプル/ダウンミックスして加算合成する。
- **セッション探索 `src/recordings.rs`（仮）**。`recording_dir` を走査し、`%Y%m%d-%H%M%S` 名の
  ディレクトリを列挙、各セッションの `RecordingSession { datetime, dir, has_mic, has_system,
  has_transcript }` を作り、新しい順に並べる。`recording_dir` は信頼境界外なので、名前が日時
  形式でないもの・ファイル欠落は安全にスキップ（落とさない）。
- **文字起こし読み込み**。`mic.json` / `system.json` を `serde` でパースして
  `TranscriptSegment { start_secs, end_secs, text, source }` の列にする。両音源をマージして
  `start_secs` 昇順に並べる。壊れた/欠落 JSON はスキップして「文字起こしなし」表示に縮退。
- **UI: 新規 `ui/recordings-window.slint`**。左に録音一覧、右に選択セッションの詳細
  （Play/Pause/Stop、経過/全体時間、トランスクリプトのスクロール一覧）。各セグメントは
  クリック可能で、話者ラベル＋時刻＋テキストを表示。再生中はティックで現在セグメントを
  ハイライトし、経過時間を更新する（既存の 100ms タイマーに相乗り or 専用タイマー）。
  - 初回 show はジオメトリ明示（`slint.md` のルール）。
- **トレイ配線**。`tray.rs` に「Recordings…」項目を追加（`Start Recording` / `Settings` /
  `Recordings…` / `Quit`）。`main.rs` のメニューイベント処理で当該ウィンドウを開く。

### 文字起こし JSON スキーマ（#30 との契約）

本ビューが読む形（#30 が生成側でこの形を満たす）。whisper のセグメント出力に対応:

```json
{
  "segments": [
    { "start": 0.0, "end": 3.2, "text": "こんにちは" },
    { "start": 3.2, "end": 6.8, "text": "はじめます" }
  ]
}
```

- `start` / `end` はセッション開始からの秒（浮動小数）。`text` はそのセグメントの発話。
- 追加フィールド（言語・信頼度等）は将来のために無視して読める設計にする（`deny_unknown_fields`
  を付けない）。ファイル名で話者（mic / system）を区別する。

## 実装ステップ

1. **再生基盤**: `rodio` を依存追加し、`src/player.rs` に単一ファイル（まず `mic.mp3`）を
   Play/Pause/Stop/seek/position/duration できる制御ハンドルを実装。手動で再生・シークを確認。
2. **セッション探索**: `recording_dir` を走査して `RecordingSession` 一覧を新しい順で返す関数と、
   日時パース・欠落/不正名スキップの単体テストを追加。
3. **ミックス再生ソース**: mic + system をデコードして PCM をミックスした単一シーク可能ソースを
   作る（レート/チャンネル整合を含む）。片方のみのセッションは単独再生。長さ・レート整合の
   純粋部分にテスト。`try_seek` の可否を確認し、非対応なら「オフセットから作り直す」フォールバック。
4. **文字起こし読み込み**: 上記スキーマの `mic.json` / `system.json` をパースしてマージする
   `Transcript` を実装。正常・欠落・壊れ JSON の単体テスト。秒→セグメントの対応（ハイライト用）も。
5. **Recordings ウィンドウ**: `ui/recordings-window.slint` を作り、一覧・詳細・トランスクリプト・
   再生ボタン・時間表示を配置。Rust 側でモデルへ流し込み、選択で詳細を更新。
6. **配線**: トレイに「Recordings…」を追加し、`main.rs` でウィンドウを開く。再生ボタン→player、
   セグメントクリック→`player.seek(start_secs)`、ティックで経過時間更新と現在セグメントの
   ハイライト。保存を伴う操作は無いが、失敗（デコード/デバイス）時はログして落とさない。
7. **縮退状態**: 録音ゼロ・文字起こし未生成（#30 前）・再生エラーの表示を整える
   （「No recordings」「Not transcribed yet」等、英語文言）。
8. **仕上げ**: `cargo build` / `cargo fmt --check` / `cargo clippy --all-targets -- -D warnings` /
   `cargo test` を通す。実機で一覧→再生→セグメントスキップを目視確認。

## 影響範囲・リスク

- **影響を受けるファイル/モジュール**:
  - 新規: `src/player.rs`、`src/recordings.rs`（探索＋文字起こし読み込み。分割してもよい）、
    `ui/recordings-window.slint`。
  - 変更: `Cargo.toml`（`rodio` 追加）、`build.rs`（新 `.slint` のコンパイル）、`src/main.rs`
    （ウィンドウ生成・メニュー配線・ティック）、`src/tray.rs`（メニュー項目追加）。
  - 依存: `Config::recording_dir` を読む（変更なし）。
- **リスクと対策**:
  - **#30 未実装**: 文字起こし表示・スキップは #30 の JSON に依存。順序として #30 を先に完了させる
    （ユーザー確定）。本ビューは JSON 非存在時に「Not transcribed yet」で縮退し、再生自体は #30 に
    依存せず動くようにしておく（早期に価値が出る）。
  - **ミックスのレート/チャンネル不一致**: mic（入力デバイス）と system（ScreenCaptureKit）で
    サンプルレート・チャンネル数が異なりうる。共通レートへリサンプルしてから加算合成する。
    実装が重ければ v1 は「共通レートのときは合成、違えば mic 優先で単独再生」に縮退してもよい
    （その旨ログ）。
  - **シーク対応**: rodio のシークはソース種別に依存。メモリ内ソースが `try_seek` 非対応なら、
    目的オフセットからソースを作り直して再生し直すフォールバックにする。
  - **常駐 UI とスレッド**: 再生スレッドと Slint メインスレッドの共有は録音同様チャネル/ハンドルで
    行い、UI をブロックしない。ウィンドウ 2 枚目でも `run_event_loop_until_quit()` の常駐は維持。
    2 枚目ウィンドウの初回 show はジオメトリ明示（`slint.md`）。
  - **大きめの機能**: 再生基盤（ステップ1–3）と文字起こし/UI（4–7）で価値が分かれるため、
    issue 化時に「再生＋一覧」と「文字起こし表示＋スキップ」へ分割する余地がある（#30 完了後）。
