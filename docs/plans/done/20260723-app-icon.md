# アプリアイコンの作成とメニューバーアイコンの差し替え

- 作成日: 2026-07-23
- ステータス: ドラフト
- **改訂: 2026-07-25 — 以下の 5 点は issue #89 で改訂済み。実装は issue #89 を参照すること。**
  1. マスターは SVG 単体ではなく **Icon Composer 形式 `.icon`**（`icon.json` + `Assets/*.svg`）。
     `xcrun actool` 一発で Tahoe 用 `Assets.car` と旧 macOS 用 `.icns` の両方が出る。
  2. `.icns` は `actool` 経由で作る（Tahoe 規定の余白が入る）。`ictool` の直接書き出しは余白ゼロで NG。
  3. メニューバーにアプリアイコンを流用しない（Tahoe のガラス質 squircle は 18pt で識別不能）。
     同じ SVG から作る**モノクロ template 画像**を別資産にする。
  4. **赤ポッチ（バッジ）案は破棄**。template 画像は色を捨てるため赤が黒になる。
     「待機 = template のモノクロ／録音中 = 非 template でグリフ全体を赤く明滅」とする。
  5. `tray.png` は 32x32 ではなく **36x36**（`tray-icon` は表示高さを 18pt 固定にするため、
     Retina 2x = 36px。グリフの余白はトリムして高さいっぱいに収める）。

## 概要

openshoki のアプリアイコン（macOS `.icns`）を新規に作成し、メニューバー（トレイ）の
常駐アイコンを暫定のグレードットからアプリアイコンへ差し替える。録音中は左上に赤ポッチ
（バッジ）を重ねて状態を示す。アイコンのデザインは Claude Design で作成する
（設定ウィンドウ・Recordings ウィンドウと同じフロー）。

## 背景・前提（コンテキスト）

- 現在アプリアイコンは存在しない。配布用 `.app` バンドルの生成は issue #20（オープン）の
  スコープで、`Info.plist`（`CFBundleIconFile`）への統合はそちらで行う。本プランは
  **アイコン資産の作成と生成パイプラインの整備、トレイへの適用まで**。
- トレイの常駐アイコンは `src/tray.rs` の `dot_icon()` がプログラム描画するドット
  （待機=グレー `IDLE_COLOR`、録音中=赤の明度補間 `recording_color(level)` で breathing）。
  コメントで「暫定アイコン」と明記されている。
- メニュー項目アイコン（Record/Stop/Settings/Recordings/Quit）は `assets/menu/*.png`
  （32x32・8bit RGBA）を `include_bytes!` で埋め込み、`png` クレートでデコードして使う
  （`docs/CONTEXT.md`: `.app` の Resources パス解決に依存しない方式）。
- アイコン生成に使えるツールがローカルにある: `rsvg-convert`（SVG→PNG）、
  `iconutil`（iconset→icns）、`magick`。CI（GitHub Actions macos ランナー）にも
  `iconutil` は標準で入る。
- Claude Design プロジェクト: https://claude.ai/design/p/2d761dcc-fbcf-4fd7-8cc6-c5a58d0d036c

## 要件

- アプリアイコンを作成する（1024x1024 マスター → `.icns`）。モチーフは**筆・「書」**
  （openshoki = 録音を「書記」するアプリ。和風の筆・墨の要素で個性を出す）。
- メニューバーの常駐アイコンをアプリアイコンに差し替える。**待機中はアプリアイコンを
  そのまま（カラーで）表示**し、**録音中は左上に赤ポッチを重ねて表示**する。
  赤ポッチは現行の breathing（明度補間、`recording_color`）を引き継いで明滅させる。
  経過時間テキスト（`set_title`）・ツールチップの挙動は現行のまま。
- スコープ外:
  - メニュー項目アイコン（Record/Stop/Settings/Recordings/Quit）の差し替え（現状のまま）
  - `.app` バンドルへの `.icns` 統合（issue #20 のスコープ。資産の準備までを本プランで行う）
  - Windows/Linux 向けアイコン（`.ico` 等）

## 確定した論点

- **デザインは Claude Design で作成**（ユーザー回答）: これまでの UI と同じフロー。
  ただし Claude Design の成果物は HTML なので、**アイコンは SVG としてデザイン**して
  もらい、確定後に SVG マスターをリポジトリへ取り込む（PNG 手書き出しを避け、
  再生成可能にする）。
- **モチーフは筆・「書」**（ユーザー回答）: マイク×ドキュメント案・波形案より和風の
  個性を優先。
- **トレイは「待機=アプリアイコン、録音中=左上に赤ポッチ」**（ユーザー回答）:
  macOS のテンプレート画像（モノクロ）慣習より、アプリの認知を優先してカラー表示する。
  ライト/ダーク両方のメニューバーで視認できる配色をデザイン要件に含める。
- **メニュー項目アイコンは現状のまま**（ユーザー回答）: 機能を表すアイコンのため対象外。
- **生成パイプラインはスクリプト化**: `rsvg-convert` で SVG → 各サイズ PNG、
  `iconutil` で `.icns` を生成する手順を `scripts/generate-icons.sh` にまとめ、
  デザイン更新時に再実行できるようにする（生成物もコミットする。ビルド時生成にはしない
  — ビルド依存を増やさないため）。

## 実装方針

1. **デザイン**: Claude Design 用プロンプト（下記）でアイコンをデザインしてもらい、
   確定した SVG を `assets/icon/openshoki.svg` に取り込む。
2. **生成**: `scripts/generate-icons.sh` が SVG から次を生成する:
   - `assets/icon/openshoki.icns`（16/32/128/256/512 の @1x/@2x を iconset に並べて
     `iconutil -c icns`）— #20 の `.app` バンドルで使用
   - `assets/icon/tray.png`（32x32 RGBA）— トレイ常駐アイコン用
3. **トレイ差し替え**（`src/tray.rs`）:
   - `tray.png` を `include_bytes!` で埋め込み、`png` クレートでデコード
     （`load_menu_icon` と同じ方式。起動時に 1 回デコードして使い回す）。
   - `set_idle`: `dot_icon(IDLE_COLOR)` → アプリアイコンの表示に変更。
   - `render_recording`: アプリアイコンの RGBA バッファに、左上へ赤ポッチ
     （円、色は `recording_color(level)`）を合成して `set_icon` する。
     合成は純粋関数（`compose_recording_badge(base: &[u8], level: f32) -> Vec<u8>` 相当）
     にしてテスト可能にする。
   - `dot_icon` は不要になれば削除（`IDLE_COLOR` も）。`recording_color` は
     ポッチの色として存続。
4. **検証**: 実アプリを起動して screencapture でライト/ダーク両方のメニューバー表示を
   目視確認（`docs/rules/slint.md` の検証方針に準拠）。合成関数はユニットテストで
   「ポッチ領域が赤・領域外がベース画像のまま」を確認する。

### Claude Design 用プロンプト（デザイン依頼時にそのまま渡す）

```
openshoki（macOS のメニューバー常駐の録音・文字起こしアプリ。名前は「書記」に由来）の
アプリアイコンをデザインしてください。

- モチーフ: 筆・「書」。和風の筆（毛筆）や墨の要素を使い、「音声を書き取る」アプリで
  あることを表現する。マイクや音声波形の要素を小さく組み合わせてもよい。
- 形式: SVG で作成（後で 1024x1024 にラスタライズして .icns 化するため、ベクターで）。
  macOS Big Sur 以降の角丸正方形（squircle、1024x1024 中の約 824x824 が本体）の
  スタイルに従う。
- バリエーション: 配色・構図の異なる案を 3〜4 案、並べて提示してください。
- 制約:
  - 32x32 に縮小してメニューバーに表示しても図案が潰れないシンプルさにする
    （メニューバー用に単純化した版を併記してもよい）。
  - メニューバーはライト/ダーク両テーマがあるため、どちらの背景でも視認できる配色にする。
  - 文字（ラテン文字・漢字）を入れる場合は 32px で判読不能になるため装飾として扱う。
```

## 実装ステップ

1. Claude Design でアイコンをデザインする（上記プロンプト。ユーザーがデザインを確定し、
   URL をもらって SVG を取得する）。
2. `assets/icon/openshoki.svg` にマスターを取り込み、`scripts/generate-icons.sh` を作成。
   実行して `openshoki.icns` / `tray.png` が生成されることを確認する。
3. `src/tray.rs` を差し替える: 埋め込み PNG のデコード、`set_idle` のアプリアイコン表示、
   `render_recording` の赤ポッチ合成（純粋関数＋テスト）。`cargo build/clippy/test` 通過。
4. 実機で目視確認: 待機表示・録音開始（ポッチ明滅・経過時間）・停止で待機へ戻る、を
   ライト/ダークで screencapture 確認。
5. README（機能説明のトレイ表示記述があれば）と `docs/CONTEXT.md`（アイコン資産と
   生成パイプラインの前提）を同期する。
6. issue #20 に「`assets/icon/openshoki.icns` を `CFBundleIconFile` で使う」旨を
   追記する（バンドル統合時の取りこぼし防止）。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール: `src/tray.rs`（`dot_icon`/`set_idle`/
  `render_recording`）、`assets/icon/`（新規）、`scripts/generate-icons.sh`（新規）、
  README / docs/CONTEXT.md、issue #20（参照追記）
- リスクと対策:
  - **カラーアイコンのメニューバー視認性**: ライト/ダーク両テーマでの視認をデザイン
    要件に明記し、実機の screencapture で両テーマを確認する。
  - **32px で図案が潰れる**: デザイン段階で 32px 縮小版の確認を依頼。必要なら
    トレイ用に単純化した派生 SVG を用意する（`tray.png` の元を分ける）。
  - **録音中表示の視認性低下**: 現行は「アイコン全体が赤く明滅」で分かりやすい。
    赤ポッチが小さすぎると気づけないため、ポッチ径はアイコンの 40% 程度から目視で調整
    する。経過時間テキストは現行どおり併記されるため補助になる。
