# 録音停止時に音声を自動で文字起こしして保存する

- 作成日: 2026-07-10
- ステータス: ドラフト

## 概要

録音セッションを停止したとき、設定で有効化されていれば、保存した各音源（`mic.mp3` /
`system.mp3`）をローカルの whisper.cpp で自動的に文字起こしし、セグメントごとの発話時間
（開始・終了）付きの JSON をセッションディレクトリに保存する。後から「このテキストは音声の
どこか」を辿れるようにし、会議録音の見返しに使えるようにする。

## 背景・前提（コンテキスト）

- 録音セッションは `<保存先>/<日時>/` にまとめ、音源ごとに固定名で保存する（`mic.mp3`＝
  マイク＝自分の声、`system.mp3`＝システム音声＝相手の声）。CONTEXT.md は当初から
  「**文字起こし結果も同じセッションディレクトリへ**」を想定している。
- `Recorder::stop()` は各音源を止め flush してファイルを確定し、**保存できたパスの一覧
  （`Vec<PathBuf>`）をメインスレッドに返す**（`src/recorder.rs`）。`src/main.rs` の
  `toggle_recording` の停止側がこれを受け取り、保存パスをログしている。→ この戻り値を起点に
  文字起こしを起動できる（手動停止・#26 の自動停止どちらの経路でも同じ）。
- 録音は機微データ。ファイルは Unix で 0600、セッションディレクトリは 0700 で作成している
  （`create_recording_file` / `create_session_dir`）。文字起こし結果も同じ機微データとして扱う。
- 設定は `Config`（`src/config.rs`）に TOML 永続化。設定画面は `ui/app-window.slint`、ファイル
  選択は `rfd` を使用済み。`Recorder`／`cpal::Stream` は `!Send` でメインスレッド保持。
- 既存の自動開始・停止（#25 / #26 / #28）とは独立。本機能は「停止後」に走るため、手動停止でも
  #26 の自動停止でも動く（ハード依存なし）。

調査で確定した技術前提:

- **ローカル whisper.cpp（`whisper-rs`）で文字起こしする**。オフライン・オンデバイスで完結し、
  会議音声を外部送信しない（プライバシー方針と整合）。セグメント単位の開始/終了タイムスタンプを
  取得できる。ビルドに C++ ツールチェーン（cmake 等）が要り、実行には**モデルファイル**が要る。
- whisper-rs は **16kHz・モノラル・f32 PCM** を入力に取る（ファイルを直接読まない）。保存物は
  MP3 のため、**文字起こし時に MP3 → PCM(16kHz/モノラル) へデコード＋リサンプル**する必要がある
  （録音側は変更せず、停止後に読み直してデコードする）。デコードは `symphonia`（mp3）または
  `minimp3` 系、リサンプルは `rubato` 等を想定。
- 文字起こしは秒〜分オーダーで重い。**メインスレッド（Slint ループ）をブロックしない**よう、
  バックグラウンドのワーカースレッドで実行する（既存のトレイ/録音はメインスレッドのまま）。

## 要件

- 設定「録音停止時に自動文字起こし」を有効化しているとき、`Recorder::stop()` で保存できた各音源
  ファイルを、停止後にバックグラウンドで文字起こしする。
- 対象は**音源ごとに別々**（`mic.mp3` → `mic.json`、`system.mp3` → `system.json`）。既存の
  「音源ごとに別ファイル」方針と揃える。
- 出力は **JSON**。各セグメントに開始時刻・終了時刻（秒）とテキストを持ち、どの音源かも分かる
  ようにする（後から音声の再生位置に対応づけられる）。
- 設定はオプトイン（**既定 OFF**）。CPU 負荷が大きいため、明示的に有効化したときだけ走らせる。
- 文字起こしにはローカルの whisper モデルファイルが必要。設定でモデルのパスを指定できる。
  未指定／存在しない場合は文字起こしをスキップしてログを残す（アプリ・録音は落とさない）。
- スコープ外:
  - 2 音源を 1 タイムラインに統合した話者付き議事録（音源別 JSON を出すに留める。統合は後続）。
  - 過去録音を後から手動で文字起こしする UI（今回は「停止直後の自動実行」のみ）。
  - 文字起こし結果の閲覧・音声再生・シーク UI（データ形式だけ用意し、UI は後続）。
  - モデルの自動ダウンロード（当面はユーザーがモデルを配置しパスを指定）。
  - 単語（word）単位のタイムスタンプ（セグメント単位に留める）。

## 確定した論点

ユーザー確認で決定:

- **エンジン**: ローカル whisper.cpp（`whisper-rs`）。オフライン・機微データを外部送信しない。
- **対象音源**: 音源ごとに別々（mic と system をそれぞれ文字起こし）。
- **保存形式**: JSON（セグメントの start/end/text）。
- **自動実行**: 設定でオプトイン、既定 OFF。

調査で確定した設計上の前提:

- **停止経路にフックする**: `toggle_recording` の停止側（と #26 の自動停止）で得た保存パスを、
  文字起こしジョブとしてバックグラウンドワーカーに渡す。
- **ワーカーは逐次処理**: whisper は CPU 集約のため、ジョブは 1 本のワーカースレッド＋キュー
  （`mpsc`）で順に処理する（複数録音が続いても thread を無制限に増やさない）。
- **モデルはユーザー指定パス**: `.app` に巨大モデルを同梱せず、ネットワーク送信も避けるため、
  設定でモデルファイルのパスを持つ（`rfd` で選択）。既定言語は auto-detect（日本語会議を想定）。

## 実装方針

- **新規 `src/transcribe.rs`**: 文字起こしの中核。
  - MP3 → PCM(16kHz/モノラル/f32) デコード＋リサンプル（`symphonia`/`rubato` 等）。
  - `whisper-rs` でモデルを読み、PCM を渡してセグメント（開始/終了/テキスト）を得る。
  - 結果を JSON（`{ source, model, language, duration_secs, segments: [{ start, end, text }] }`）に
    シリアライズし、音源と同じディレクトリへ音源名ベースで書く（`mic.json` 等、0600 で作成）。
  - モデル未指定/欠如・デコード失敗・whisper 失敗は握りつぶさずログし、他音源・アプリは巻き込まない。
- **バックグラウンドワーカー**: 起動時に文字起こしワーカースレッドと送信チャネルを 1 本用意する。
  ジョブ（対象パス群＋モデルパス＋言語）を送ると逐次処理する。メインスレッドは投げるだけ。
- **`src/main.rs`**: 停止処理後、設定 ON かつモデルパスありなら、`Recorder::stop()` が返した
  保存パスからジョブを組み立ててワーカーへ送る。手動停止・#26 の自動停止の両経路で同じ関数を通す。
  （任意）トレイのツールチップに「文字起こし中…」を出す簡易フィードバックは後続でも可。
- **`src/config.rs`**: `auto_transcribe: bool`（既定 false）、`whisper_model_path: Option<PathBuf>`、
  `transcribe_language: Option<String>`（既定 None=auto）を追加。すべて **`#[serde(default)]`** で
  旧 TOML 互換を保つ。ラウンドトリップのテストを足す。
- **`ui/app-window.slint`**: 自動文字起こしのトグルと、モデルファイル選択（`rfd` の `pick_file`）を
  追加。追加/変更は Rust 側コールバックで `Config::save()` により永続化・起動時復元する。高さが
  足りなければ `WINDOW_HEIGHT` と `min-height` を揃えて調整。
- **`Cargo.toml`**: `whisper-rs`、MP3 デコード（`symphonia` など）、リサンプル（`rubato` など）、
  `serde_json` を追加。whisper.cpp のビルド（C++/cmake）と、macOS での Metal 有効化可否を確認。

## 実装ステップ

1. **`Config` に設定を追加**（`auto_transcribe`・`whisper_model_path`・`transcribe_language`、
   `#[serde(default)]`、ラウンドトリップテスト）。
   - 検証: 既存項目のみの TOML を読んでも成功し既定になる（`cargo test`）。
2. **MP3 → PCM(16kHz/モノラル) デコード＋リサンプルを実装**（純粋処理として切り出しテスト）。
   - 検証: 既知の短い MP3 を渡すと想定サンプルレート・チャンネルの PCM が得られる（単体テスト or
     暫定確認）。
3. **`whisper-rs` でモデル読込→PCM 文字起こし→JSON 出力を実装**（`transcribe.rs`）。
   - 検証: モデルを配置し、テスト音声からセグメント（start/end/text）付き JSON が生成される。
     モデル欠如・デコード失敗時はスキップしてログ。`cargo build`／`clippy`／`fmt`。
4. **バックグラウンドワーカー＋停止フックを実装**（`main.rs`）。設定 ON・モデルありのとき停止後に
   ジョブ投入、逐次処理。
   - 検証: 録音停止後、UI をブロックせずに `mic.json`（あれば `system.json`）が生成される。設定
     OFF・モデル未指定では実行されない。
5. **設定 UI（トグル＋モデル選択）を実装**し、永続化・起動時復元。
   - 検証: トグルとモデルパスが保存され、再起動後も保持。レイアウトが崩れない（`docs/rules/slint.md`）。
6. **目視の総合確認**: 実際に録音→停止→少し待つ→`mic.json`/`system.json` にタイムスタンプ付きの
   文字起こしが保存されることを確認。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - 追加: `src/transcribe.rs`（デコード＋whisper＋JSON 出力）、バックグラウンドワーカー。
  - 変更: `src/main.rs`（停止フック・ワーカー起動）、`src/config.rs`（設定）、
    `ui/app-window.slint`（トグル＋モデル選択、必要なら `WINDOW_HEIGHT`）、`Cargo.toml`（依存）。
  - 変更なし: `src/recorder.rs`／`src/system_audio.rs`（`stop()` の戻り値を利用するだけ）。
- リスクと対策:
  - **ビルドの重さ・時間**: whisper.cpp（C++/cmake）をビルドするため CI/ローカルのビルド時間・
    ツールチェーン要件が増える。CI（macos-latest）で通るか、リリース（#20 の `.app`）に載るかを確認。
  - **モデルの入手・サイズ**: `.app` 同梱は巨大。当面ユーザー配置＋パス指定とし、推奨モデル
    （精度/速度のバランス）をドキュメント化。自動ダウンロードは後続。
  - **処理時間・CPU 負荷**: 長時間録音は文字起こしに時間がかかる。逐次ワーカーで直列化し、既定
    OFF のオプトインにする。macOS の Metal 等アクセラレーションの活用を検討。
  - **常駐終了時の未完了ジョブ**: アプリ終了時に文字起こし中だと結果が失われうる。MVP では
    ベストエフォート（未完了はログ）とし、終了時の待機やジョブの永続キューは後続で検討。
  - **MP3 再デコードの品質**: 保存用に MP3 圧縮した音声を戻して認識するため、原音より精度が
    落ちうる。必要なら将来、認識用に無圧縮 PCM を一時保持する案を検討（今回は再デコードで進める）。
  - **タイムスタンプ基準**: JSON の start/end は各音源ファイルの先頭からの相対秒。mic と system は
    ほぼ同時刻に開始するが厳密には一致しないため、2 音源の突き合わせ（統合）はスコープ外とする。
