# マイクが使われなくなったら録音を自動停止する

- 作成日: 2026-07-10
- ステータス: 改訂済み（issue #26 が最新）

> **改訂メモ（2026-07-10）**: 本プランの「マイク入力を使うプロセスが無くなったら停止」という
> 停止条件は、オンラインミーティング録音の用途に合わせて **「登録ミーティングアプリの音声出力が
> 止まったら（＝通話終了）停止」** へ見直した。理由: ミーティングアプリはミュート中もマイク入力を
> 掴み続ける／逆にミュートで解放するアプリもあり入力を合図にすると早期停止しうる一方、参加者の
> 音声は通話中ずっと出力されるため出力の停止が通話終了の堅牢な合図になるため。最新の条件・依存
> （#28 のアプリ登録＋出力検知を再利用、順序 #25 → #28 → #26）は **issue #26** を参照。

## 概要

#25（マイク使用検知で録音を自動開始）で自動的に始めた録音を、会議アプリなどの外部プロセスが
マイクを使い終えたタイミングで自動停止する。会議の終了に追従して録音を閉じ、撮りっぱなしを
防ぐ。#25 と合わせて「マイク使用に連動して録音する」一連の挙動を完成させる。

## 背景・前提（コンテキスト）

- 本アプリはメニューバー常駐型で、録音はマイク（`cpal`、必須）＋ システム音声（macOS
  `screencapturekit`、任意）で構成する（`docs/CONTEXT.md`、`src/recorder.rs`）。
- 停止処理は実装済み: `Recorder::stop()` が各音源を止め flush してファイルを確定し、`main.rs`
  の `toggle_recording` の停止側が呼ぶ。本機能は**この既存の停止経路を自動で呼ぶ**だけで、
  停止そのものの仕組みは変えない。
- 別スレッドのイベントを `slint::Timer`（`MENU_POLL_INTERVAL` = 100ms）でメインループへ
  橋渡しするパターンが既にある。`Recorder` は `!Send` で、開始・停止はメインスレッド上で行う。
- **#25 が前提（依存）**。#25 で新設される想定の基盤に乗る:
  - `src/mic_monitor.rs`（macOS の CoreAudio マイク監視モジュール）
  - 設定 `auto_record_on_mic_active`（`Config`）と設定画面トグル
  - `toggle_recording` の開始側を切り出した `start_recording`
  本プランはこれらを拡張する（#25 未実装のうちは着手しない）。

調査で確定した技術前提（本機能の肝）:

- **デバイスレベルの信号は自プロセスの録音でマスクされる**: 自動開始で自分が `cpal` を通じて
  既定入力デバイスを掴むと、`kAudioDevicePropertyDeviceIsRunningSomewhere`（#25 で使う「稼働中
  か」）は自分の稼働で真のままになり、外部アプリの解放を同じ信号では検知できない。
- **そのため「外部プロセスの入力使用」を直接見る**: macOS 14.4+ の CoreAudio プロセスオブジェクト
  API を使う。`kAudioHardwarePropertyProcessObjectList` でプロセスオブジェクト一覧を取り、各
  プロセスの `kAudioProcessPropertyIsRunningInput`（入力稼働中か）と `kAudioProcessPropertyPID`
  （PID）を見て、**自プロセス（`std::process::id()`）以外に入力稼働中のプロセスがあるか**を判定
  する。これが「会議アプリがまだマイクを使っているか」に対応する。
- macOS 14.4 未満ではこの API が無いため、**自動停止は無効化**（機能自体は落とさず、停止は
  従来どおり手動）。#25 の自動開始は macOS 13+ で動くまま。

## 要件

- 設定が ON で、かつ **#25 により自動開始した録音**が実行中のとき、自プロセス以外に入力稼働中の
  プロセスが無くなった（＝外部アプリがマイクを手放した）ら、その録音を自動停止する。
- 自動停止は既存の停止経路（`Recorder::stop` → 各音源 flush → ファイル確定 → メニュー表示を
  待機に戻す）を使い、手動停止と同じ結果（保存物・メニューバー表示）にする。
- 誤停止を避けるため、外部入力が無い状態が**短い猶予時間（デバウンス）継続**してから停止する。
- 設定は #25 と同じトグル（`auto_record_on_mic_active`）に統合し、開始・停止を一体の挙動にする
  （新しい設定項目は増やさない）。
- スコープ外:
  - **手動開始した録音の自動停止**（外部アプリ未使用でも勝手に止めない）。自動停止の対象は
    自動開始した録音のみ。
  - macOS 14.4 未満での自動停止（API 非対応のため無効）。
  - Windows / Linux での自動停止（CoreAudio 依存のため macOS のみ）。
  - 無音・発話区間に基づく停止（会議中の沈黙で止まってしまうため採らない）。

## 確定した論点

ユーザー確認で決定:

- **検知方式**: 外部プロセスのマイク入力監視（macOS 14.4+ のプロセスオブジェクト API）。
  デバイス信号が自録音でマスクされる制約を、プロセス単位の入力稼働判定で回避する。無音検知は
  会議中の沈黙で止まるため採らない。
- **適用範囲**: 自動開始した録音のみ（手動録音は外部アプリ未使用でも即停止しないよう保護）。
- **設定**: #25 と同じトグルにまとめ、開始・停止を「マイク使用に連動して録音」の一連の挙動とする。

調査で確定した設計上の前提:

- **判定はポーリング**で行う。プロセスの出入り・各プロセスへのリスナー登録は入れ替わりが激しく
  脆いため、自動開始した録音の実行中だけ、既存タイマーに相乗りして数百 ms 〜 1 秒間隔で
  「自分以外に入力稼働中のプロセスがあるか」を問い合わせ、真→偽の遷移（＋デバウンス）で停止する。
- **自分の PID を除外**する（自録音で自分は必ず入力稼働中になるため）。
- **録音の由来を追跡**する。`main.rs` の録音状態（`Option<Recorder>`）に「自動開始かどうか」の
  フラグを併せ持ち、自動停止はそのフラグが真のときだけ発火させる。

## 実装方針

- **`src/mic_monitor.rs` を拡張**（macOS 14.4+ 対応の問い合わせを追加）:
  - `external_input_active() -> Option<bool>` を追加する。プロセスオブジェクト一覧を取得し、
    自 PID 以外に `IsRunningInput == true` のプロセスがあれば `Some(true)`、無ければ `Some(false)`。
    API 非対応（macOS 14.4 未満）や取得失敗時は `None`（＝自動停止を行わない合図）。
  - CoreAudio のセレクタ（`kAudioHardwarePropertyProcessObjectList` / `…IsRunningInput` /
    `…PID`）はバインディング（`coreaudio-sys`）に無ければ FourCC 定数を明示定義し、
    `AudioObjectGetPropertyData` を直接叩く（`unsafe` は薄いラッパへ隔離、`system_audio.rs` と
    同じ方針）。
- **`src/main.rs`**:
  - `toggle_recording` の停止側を `stop_recording` として切り出す（#25 の `start_recording` と
    対称。挙動不変のリファクタ）。
  - 録音状態に「自動開始フラグ」を持たせる（例: `recorder: Option<Recorder>` の隣に
    `auto_started: bool`、または `(Recorder, bool)` に束ねる）。#25 の自動開始経路では真、
    手動開始では偽をセットする。
  - タイマー処理に自動停止ロジックを追加する: 設定 ON かつ録音中かつ `auto_started` のとき、
    数 tick ごとに `external_input_active()` を確認。`Some(false)` がデバウンス期間継続したら
    `stop_recording` を呼ぶ。`Some(true)` で猶予カウンタをリセット、`None` は何もしない
    （非対応環境）。デバウンス秒数はチューニングしやすいよう定数化する。
- **設定・UI**: #25 のトグル（`auto_record_on_mic_active`）をそのまま使う。新規追加なし。

## 実装ステップ

1. **`stop_recording` を切り出す**（`toggle_recording` の停止側、挙動不変）。
   - 検証: 手動の開始／停止が従来どおり動く（`cargo build`／目視）。
2. **録音状態に自動開始フラグを追加**し、#25 の自動開始経路で真、手動開始で偽をセットする。
   - 検証: 自動開始・手動開始それぞれでフラグが期待どおり（デバッグログ等で確認）、
     `cargo build`／`cargo clippy --all-targets -- -D warnings`。
3. **`mic_monitor` に `external_input_active()` を実装**（プロセスオブジェクト API、自 PID 除外、
   非対応/失敗時は `None`）。
   - 検証: 会議アプリでマイク使用中は `Some(true)`、終了後は `Some(false)`、macOS 14.4 未満では
     `None` を返す（暫定ログで確認）。単体テスト可能な純粋部分（判定ロジック）は切り出してテスト。
4. **`main.rs` タイマーに自動停止ロジック**（設定 ON・自動開始録音・デバウンス付き）を追加する。
   - 検証: 自動開始した録音が、外部アプリのマイク解放後にデバウンス期間を経て自動停止し、
     `mic.mp3`（あれば `system.mp3`）が確定保存される。手動録音は自動停止しない。設定 OFF・
     macOS 14.4 未満では自動停止しない。
5. **目視の総合確認**: 会議アプリ開始→自動録音開始（#25）→会議終了→自動停止→保存物確認、の
   一連が通ること。短時間のマイク断（デバイス切替など）で誤停止しないこと。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - 変更: `src/mic_monitor.rs`（外部入力問い合わせを追加）、`src/main.rs`（`stop_recording`
    切り出し・自動開始フラグ・タイマーの自動停止ロジック）。
  - 変更なし: `src/recorder.rs`／`src/system_audio.rs`（既存の `stop()` を再利用）、
    `src/config.rs`／`ui/app-window.slint`（#25 のトグルを流用、新規項目なし）。
- リスクと対策:
  - **CoreAudio 新セレクタのバインディング有無**: `coreaudio-sys` が macOS 14.4 の
    プロセスオブジェクト系セレクタを露出していない可能性。無ければ FourCC 定数を明示定義して
    直接問い合わせる。実装時にセレクタ値を SDK ヘッダで確認する（「未確定事項」）。
  - **macOS 14.4 未満での非対応**: `external_input_active()` が `None` を返し自動停止を行わない。
    起動時に一度ログして利用者に分かるようにする。自動開始（#25）は 13+ で動くまま。
  - **誤停止（短時間のマイク断）**: デバイス切替等で一瞬 `false` になりうる。デバウンス
    （数秒の猶予）で緩和し、秒数は定数で調整可能にする。
  - **ポーリング負荷**: プロセスオブジェクト一覧の取得を録音中のみ・数百 ms〜1 秒間隔に抑える。
    待機中は問い合わせない。
  - **#25 への依存**: 基盤（`mic_monitor`／設定／`start_recording`）が未実装のうちは着手不可。
    #25 完了後に着手する。

## 未確定事項

- CoreAudio プロセスオブジェクト系セレクタの正確な値・バインディング可否（実装着手時に SDK
  ヘッダ／`coreaudio-sys` の中身で確認。必要なら FourCC 定数を明示定義）。
- デバウンス秒数の初期値（実機の会議アプリ挙動を見て調整。まず 2〜3 秒程度を想定）。
- ポーリング間隔（100ms タイマーの何 tick ごとに問い合わせるか。負荷と追従性のバランスで決定）。
- 複数の外部アプリが同時にマイクを使う場合、最後の 1 つが解放されるまで止めない扱いでよいか
  （現方針はそれで整合するが、実機で確認）。
