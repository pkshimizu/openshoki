# 事前に設定したアプリが音声を再生したら録音を開始する

- 作成日: 2026-07-10
- ステータス: ドラフト

## 概要

ユーザーが事前に登録したアプリ（`.app`）が音声を再生し始めたことを検知し、録音セッションを
自動で開始する。#25（マイク使用検知で自動開始）の兄弟機能で、トリガーが「特定アプリの音声
**出力（再生）**」になる。会議アプリや動画・通話アプリの再生開始を起点に録音を撮り逃さない。

## 背景・前提（コンテキスト）

- 本アプリはメニューバー常駐型で、録音はマイク（`cpal`、必須）＋ システム音声（macOS
  `screencapturekit`、任意）で構成する（`docs/CONTEXT.md`、`src/recorder.rs`）。
- 別スレッドのイベントを `slint::Timer`（`MENU_POLL_INTERVAL` = 100ms）でメインループへ
  橋渡しするパターンがある。`Recorder` は `!Send` で、開始はメインスレッド上で行う。
- 設定は `Config`（`src/config.rs`）に持ち TOML で永続化。設定画面は `ui/app-window.slint`。
  フォルダ選択は `rfd`（ネイティブダイアログ）を既に使用（`on_choose_folder`）。
- macOS では `objc2` / `objc2-app-kit`（`NSApplication` 等）を既に利用している。
- **依存関係**:
  - **#25 が前提**。#25 で新設される想定の基盤に乗る（`toggle_recording` の開始側を切り出した
    `start_recording`、自動開始の設定・UI パターン、タイマー橋渡し、録音の「自動開始フラグ」）。
  - **#26 のプロセスオブジェクト照会を再利用**。#26（マイク未使用で自動停止）が macOS 14.4+ の
    CoreAudio プロセスオブジェクト API 照会を導入する。本機能はその出力版
    （`kAudioProcessPropertyIsRunningOutput`）を使うため、#26 後に着手するか、照会処理を共通
    ヘルパへ切り出して共有する。

調査で確定した技術前提:

- **アプリ単位の音声出力検知には macOS 14.4+ のプロセスオブジェクト API が必要**。
  `kAudioHardwarePropertyProcessObjectList` でプロセスオブジェクト一覧を取り、各プロセスの
  `kAudioProcessPropertyIsRunningOutput`（出力稼働中か）と `kAudioProcessPropertyPID`（PID）を
  見る。PID → アプリの対応は `NSRunningApplication.runningApplicationWithProcessIdentifier:` の
  `bundleIdentifier` で取る。これで「登録アプリが再生中か」を判定できる。macOS 14.4 未満では
  この機能は無効（アプリは落とさない）。
- **`.app` からバンドル ID を得る**: `rfd` の `pick_file`（`.app` 拡張子フィルタ）で `.app` を選ばせ、
  `NSBundle(url:).bundleIdentifier`（`objc2` 経由）で取得して保存する（新しい plist クレートは
  増やさない）。表示名も併せて保持する。

## 要件

- 設定でこの機能を有効化し、1 つ以上のアプリを登録できる。登録は `.app` をネイティブダイアログ
  （`rfd`）で選び、バンドル ID（＋表示名）を保存する。**複数登録可**。
- 機能が有効で、登録アプリのいずれかが音声出力を**非稼働→稼働**へ変化させたとき、録音中で
  なければ録音セッションを自動開始する。開始は既存の手動開始と同じ経路（`Recorder::start`）を
  使い、保存物・メニュー表示（停止ラベル・点滅・経過時間）は手動時と同一にする。
- 設定はオプトイン（既定 OFF）。自動録音はプライバシーに関わるため、明示的に有効化した
  ときだけ働かせる。#25 のマイク連動とは**別トグル・別設定**にする（トリガーが異なるため）。
- スコープ外:
  - **自動停止**（登録アプリが再生をやめたら止める）。停止は手動または後続 issue
    （#26 と同じ分割方針）。
  - macOS 14.4 未満での動作（プロセス出力検知の API が無いため無効）。
  - Windows / Linux（CoreAudio 依存のため macOS のみ）。
  - 「起動中アプリ一覧から選ぶ」UI・バンドル ID の手入力（今回は `.app` 選択のみ）。

## 確定した論点

ユーザー確認で決定:

- **アプリ設定方法**: `.app` をファイルダイアログ（`rfd`）で選び、バンドル ID を保存。
- **登録数**: 複数登録可（設定はリストで持つ）。
- **自動停止**: 今回は自動開始のみ（停止は手動／後続）。

調査で確定した設計上の前提:

- **対象 OS・バージョン**: macOS のみ・macOS 14.4+（アプリ単位の出力検知に必須）。
- **設定は #25 と分離**: トリガー（マイク入力 vs 特定アプリの出力）が異なるため、別トグル・
  別リストで持つ。
- **判定はポーリング**: プロセスの出入りへのリスナー登録は脆いため、#26 と同様に既存タイマーに
  相乗りして数百 ms〜1 秒間隔でプロセスオブジェクトを照会し、登録アプリの出力が立ち上がった
  エッジで開始する（`recorder.is_none()` のときだけ）。

## 実装方針

- **`src/config.rs`: 設定を追加**する。
  - `auto_record_on_app_playback: bool`（既定 `false`）と、登録アプリのリスト
    `app_playback_triggers: Vec<AppTrigger>`（`AppTrigger { bundle_id: String, name: String }`）を
    追加。いずれも既存 TOML 互換のため **`#[serde(default)]`**。ラウンドトリップのテストを足す。
- **音声出力モニタ（プロセスオブジェクト照会の出力版）**:
  - #26 が導入するプロセスオブジェクト照会を再利用し、`outputting_bundle_ids() -> Option<Vec<String>>`
    のような「現在出力稼働中のプロセスのバンドル ID 集合」を返す関数を用意する（非対応/失敗時は
    `None`）。PID→バンドル ID は `NSRunningApplication` で解決する。
  - 置き場所は #26 のモジュール（`mic_monitor`）を音声活動監視として一般化して同居させるか、
    共通の照会ヘルパを切り出して `app_audio_monitor` から使う（実装時に #26 の構造を見て決める）。
- **`src/main.rs`: タイマーで自動開始を橋渡し**する。
  - 設定 ON かつ `recorder.is_none()` のとき、数 tick ごとに出力中バンドル ID 集合を取得し、
    登録アプリのいずれかが**新たに**出力を始めた（前回集合に無く今回集合にある）ら
    `start_recording` を呼ぶ（#25 で切り出す関数を共用、録音を「自動開始」フラグ付きで開始）。
  - #25 のマイク連動と本機能は独立に判定し、どちらの契機でも同じ `start_recording` に集約する。
- **`ui/app-window.slint`: 設定 UI を追加**する。
  - 有効化トグルと、登録アプリの一覧表示（表示名）＋「アプリを追加」ボタン（`rfd` で `.app`
    選択）＋各項目の削除。Slint のリスト（`for`）で描画する。ウィンドウ高さが足りなければ
    `src/main.rs` の `WINDOW_HEIGHT` と `ui` の `min-height` を両方揃えて調整する。
  - 追加時のバンドル ID 解決・保存、削除・トグルは `on_choose_folder` と同様に Rust 側コールバックで
    実装し、`Config::save()` で永続化・起動時復元する。
- **`Cargo.toml`**: 必要なら `objc2-foundation`（`NSBundle`/`NSRunningApplication` 用。多くは
  `objc2-app-kit` の依存として既に入っている見込み）を明示追加。CoreAudio 照会は #26 の依存
  （`coreaudio-sys` 等）を共有。

## 実装ステップ

1. **`Config` に有効化トグルと登録アプリ配列を追加**（`#[serde(default)]`、ラウンドトリップ
   テスト）。
   - 検証: 既存項目のみの TOML を読んでも成功し既定（OFF・空リスト）になる（`cargo test`）。
2. **`.app` 選択→バンドル ID/表示名の解決を実装**（`rfd` の `.app` 選択 ＋ `NSBundle` 解決）。
   - 検証: `/Applications/*.app` を選ぶと正しいバンドル ID・表示名が得られる（暫定ログ）。
3. **出力中バンドル ID 集合を返す照会を実装**（#26 のプロセスオブジェクト照会を再利用、
   PID→`NSRunningApplication`、非対応/失敗時 `None`）。
   - 検証: 対象アプリで音声再生中はそのバンドル ID が集合に含まれ、停止後は含まれない。
     macOS 14.4 未満では `None`。判定の純粋部分は単体テスト。
4. **`main.rs` タイマーに自動開始ロジック**（設定 ON・未録音・登録アプリの出力立ち上がりで
   `start_recording`）を追加。
   - 検証: 登録アプリが再生を始めると録音が自動開始し、`mic.mp3`（権限があれば `system.mp3`）が
     保存される。未登録アプリの再生や設定 OFF では開始しない。録音中は再トリガーしない。
5. **設定 UI（トグル＋アプリ一覧の追加/削除）を実装**し、永続化・起動時復元。
   - 検証: アプリを追加/削除でき、再起動後も保持。レイアウトが崩れない（`docs/rules/slint.md`）。
6. **目視の総合確認**: 登録アプリで再生開始→自動録音開始→手動停止→保存物確認。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - 追加: 音声出力モニタ（`app_audio_monitor.rs` もしくは #26 のモジュールへ同居）。
  - 変更: `src/config.rs`（設定追加）、`ui/app-window.slint`（アプリ一覧 UI）、`src/main.rs`
    （タイマー連携・アプリ追加/削除・トグルのコールバック、必要なら `WINDOW_HEIGHT`）、
    `Cargo.toml`（必要なら `objc2-foundation`）。
  - 変更なし: `src/recorder.rs`／`src/system_audio.rs`（`Recorder::start` を再利用）。
- リスクと対策:
  - **ヘルパープロセスで再生されるケース**: ブラウザや Electron/Spotify などは helper プロセスが
    音声を出し、その PID の `NSRunningApplication` が nil／別バンドル ID を返すことがある。
    対策候補: responsible pid（`responsibility_get_pid_responsible_for_pid`）で親アプリへ解決、
    もしくはバンドル ID の前方一致（例: `com.google.Chrome` に対し helper を含める）。実装時に
    実挙動を見て決める（「未確定事項」）。
  - **macOS 14.4 未満での非対応**: 照会が `None` を返し自動開始しない。起動時に一度ログする。
  - **`.app` 選択の扱い**: `NSOpenPanel`（`rfd`）は `.app` をパッケージ＝ファイルとして選択できる
    想定。フィルタ／選択挙動を実機で確認する。
  - **誤検知・意図しない録音**: 登録アプリが短時間音を出しただけでも開始しうる。既定 OFF の
    オプトインで緩和し、録音中はメニューバー表示で気付ける。必要ならデバウンスを検討。
  - **設定 UI の複雑化**: リストの追加/削除は既存の単純なトグルより手が要る。Slint の `for` と
    Rust 側モデル反映を丁寧に。
  - **依存**: #25 の基盤・#26 のプロセスオブジェクト照会が未実装のうちは着手不可（#25→#26→本機能
    の順を想定）。

## 未確定事項

   などを実装時に決定）。
- 出力検知のデバウンス要否（ごく短い再生で開始しない猶予を入れるか）。
- CoreAudio プロセスオブジェクト系セレクタ（`…IsRunningOutput` 等）のバインディング可否
  （#26 と同様、無ければ FourCC 定数を明示定義）。
- 音声出力モニタを #26 のモジュールへ同居させるか別モジュールにするか（#26 の実装構造を見て決定）。
- 自動停止（再生終了で止める）を後続 issue として起こすか。
