# オンライン LLM（Claude / OpenAI / Gemini）による文字起こし・要約の選択対応

- 作成日: 2026-07-22
- ステータス: 確定

## 概要

文字起こしと議事録要約のエンジンを「オンデバイス（既定）／オンライン LLM」から選択できる
ようにする。オンライン LLM はユーザー自身の API キーで利用し、**明示的なオプトイン**と
警告表示を条件に、選択した事業者へ音声・文字起こしを送信する。これに伴い、プロジェクトの
プライバシー方針を「外部送信しない」から「**既定では外部送信しない**（オンライン選択時のみ、
選択した事業者へ送信）」へ改定する（ユーザー確認済み）。

## 背景・前提（コンテキスト）

- 現行方針は「機微データを外部送信しないためオンデバイス限定」（CONTEXT.md、README・LP の
  売り文句）。本プランでこの方針を**改定**する（確定した論点を参照）。
- 既存基盤:
  - 文字起こし: オンデバイス whisper（`src/transcribe.rs`、逐次ワーカー、
    `mic.json` / `system.json` にセグメント時刻付きで保存）。表示（#54）はこの JSON 契約
    （`segments[].start/end/text`、秒）に依存する。
  - 要約: オンデバイス llama.cpp（#78 検証・#79 基盤・#80 生成 は完了。#81 表示は未着手）。
  - HTTP クライアントは `ureq`（whisper モデルの DL で使用。タイムアウト・サイズ上限の定型あり）。
- **各社 API の技術的事実**（Claude API リファレンスで確認済み）:
  - **Claude API は音声入力に非対応** → オンライン文字起こしは Claude では実現できない。
    要約（テキスト入力）は可能。Rust には公式 SDK が無いため raw HTTP（`ureq`）で
    Messages API（`POST /v1/messages`、`x-api-key` / `anthropic-version` ヘッダ）を叩く。
    既定モデルは `claude-opus-4-8`（現行の推奨。config で上書き可）。`max_tokens` は
    非ストリーミングの推奨値 16000。
  - **OpenAI**: 文字起こしは Whisper API（`audio/transcriptions`、`verbose_json` で
    セグメント時刻付き）が使え、**既存の JSON 契約を維持できる**。音声ファイルは
    25MB 上限。要約は Chat Completions。
  - **Gemini**: 音声入力は可能だがセグメント時刻の精度が不安定なため、文字起こしは後続
    検討。要約（テキスト）は対応する。
- API キーは資格情報。`docs/rules/security.md`（平文でログ・リポジトリに出さない）に従う。

## 要件

- 設定画面で文字起こし・要約それぞれのエンジンを選択できる:
  - 文字起こし: **On-device（既定）/ OpenAI**
  - 要約: **On-device（既定）/ Claude / OpenAI / Gemini**
- オンラインエンジンを選択するとき、「音声（または文字起こし）が選択した事業者へ送信される」
  旨の警告を設定画面に明示する。既定は常にオンデバイス（オプトイン）。
- API キーは **macOS の Keychain に保存**する（config.toml に平文で置かない。設定画面の
  入力欄はマスク表示。ログ・エラーメッセージにキーや送受信本文を出さない）。
- オンライン文字起こし（OpenAI）は既存の `mic.json` / `system.json` 契約（セグメント秒）で
  保存し、表示（#54）・要約（#80）がエンジンに依存しないようにする。
- オンライン要約は既存の議事録構成（議事概要・議題内容・決定事項・アクションアイテム、
  言語は認識言語に追従）と同じプロンプト方針を使う。
- 失敗時（キー未設定・認証エラー・レート制限・ネットワーク断）はログして縮退し、
  アプリを落とさない（既存ワーカーの縮退方針と同じ）。
- README・LP・CONTEXT.md のプライバシー記述を新方針（既定では送信しない）へ同期する。
- スコープ外:
  - Gemini / Claude での文字起こし（Claude は API 非対応、Gemini は時刻精度が課題。後続）。
  - ローカルプロキシ・Azure OpenAI 等のエンドポイント切替、ストリーミング表示。
  - macOS 以外での Keychain 相当（当面 macOS のみ。他 OS はオンラインエンジン設定を無効化）。
  - 使用量・課金の表示。

## 確定した論点

ユーザー確認で決めた事項:

- **プライバシー方針を改定する**: 「既定はオンデバイスで外部送信なし。オンライン LLM を
  明示的に選択した場合のみ、選択した事業者に音声/文字起こしを送信」。設定画面に警告を明示し、
  README・LP の文言も同時に更新する。
- **API キーは macOS Keychain に保存**（`security-framework` クレート。他 OS は当面非対応）。
- **初期範囲は「要約 3 社＋文字起こし OpenAI」**（Claude は音声入力非対応、Gemini の
  文字起こしは時刻精度が不安定なため後続）。
- **ローカル LLM 計画（#78〜#81）は維持し、エンジン抽象を先行**する。#80（ローカル要約）は
  エンジン抽象の上の 1 実装として作り、オンラインは追加エンジンとして実装する。

調査で解消した事項:

- オンライン文字起こしは OpenAI Whisper API の `verbose_json` がセグメント開始/終了秒を
  返すため、既存 JSON 契約をそのまま維持できる（表示・要約側の変更不要）。
- Claude へは raw HTTP（`ureq`）で Messages API を叩く（Rust 公式 SDK なし。`ureq` は
  既存依存でタイムアウト定型もある）。エラーは HTTP ステータス＋エラー種別で分岐し、
  レスポンス本文（文字起こし内容を含みうる）をログへ出さない。
- エンジン抽象は **enum ディスパッチ**で足りる（バリアント数が少なく、trait オブジェクトの
  複雑さが不要。ワーカーのジョブ実行時に enum で分岐する）。

## 実装方針

- **エンジン抽象（enum）**: `transcribe.rs` に `TranscribeEngine { OnDevice, OpenAi }`、
  要約側に `SummaryEngine { OnDevice, Claude, OpenAi, Gemini }` を導入し、ワーカーの
  ジョブ実行でエンジンごとの実装へ分岐する。ジョブ投入・状態管理・保存（JSON / summary.md）は
  エンジン非依存の共通部に置く。
- **資格情報**: `src/credentials.rs` を新設し、Keychain への保存・取得・削除を提供する
  （service=`openshoki`、account=プロバイダ名）。設定画面はマスク付き入力欄＋保存ボタン。
  キーはメモリ上でも使い捨て（構造体に長期保持しない）。ログに出さない。
- **オンライン要約**: プロンプト（見出し固定・話者ラベル・言語追従）はローカルと共通の
  テンプレートを使い、送信はプロバイダごとの薄い HTTP クライアント（`ureq`、
  connect/recv タイムアウト明示、429/5xx は限定リトライ）。オンラインはコンテキストが
  大きいためチャンク分割せず全文 1 リクエストを基本とし、入力サイズの安全上限だけ設ける。
  - Claude: `POST /v1/messages`（`x-api-key`、`anthropic-version: 2023-06-01`、
    既定モデル `claude-opus-4-8`、`max_tokens: 16000`）
  - OpenAI: Chat Completions（既定モデルは実装時の推奨を採用、config で上書き可）
  - Gemini: `generateContent`（同上）
- **オンライン文字起こし（OpenAI）**: `mic.mp3` / `system.mp3` を multipart で送信し、
  `verbose_json` のセグメントを既存スキーマへ変換して保存する。25MB 超のファイルは
  時間で分割して送信し、各チャンクのオフセットを start/end に加算して結合する。
- **設定**: `transcribe_engine` / `summarize_engine`（＋プロバイダ別モデル名の上書き）を
  TOML に保存（寛容デシリアライズ、不正値は既定 On-device へ丸める）。キーそのものは
  TOML に置かない。
- **文言・ドキュメント**: 設定画面の警告（英語、例: `Audio and transcripts will be sent
  to <Provider> when this engine is selected.`）、README・LP・CONTEXT.md の同期。

## 実装ステップ

1. **エンジン抽象と設定の骨組み**
   `TranscribeEngine` / `SummaryEngine` の enum と設定項目（TOML・寛容デシリアライズ）を
   追加し、既存のオンデバイス文字起こしを `OnDevice` バリアントへ整理する（挙動不変）。
   確認: 既存テストが通り、設定の保存・復元・不正値の丸めがテストで確認できる。
   ※ 要約側の抽象は #80 の実装と同時に入れる（#80 側に本プランへの参照を追記する）。
2. **Keychain 資格情報モジュールと設定画面**
   `src/credentials.rs`（保存・取得・削除、macOS のみ。他 OS はスタブで常に未設定）と、
   設定画面のエンジン選択 ComboBox・API キー入力（マスク）・警告文表示を実装する。
   確認: キーの保存→再起動→取得が動く。config.toml にキーが現れない。画面を
   screencapture で目視確認（`docs/rules/slint.md`）。
3. **オンライン要約エンジン（Claude / OpenAI / Gemini）**
   共通プロンプトテンプレート＋プロバイダ別 HTTP クライアントを実装し、要約ワーカーの
   エンジン分岐に接続する。エラー分類（認証・レート制限・ネットワーク）と限定リトライ、
   本文を含まないログ。リクエスト組み立て・レスポンス解釈の純粋部分に単体テスト
   （HTTP はモック文字列で検証）。
   確認: 各社の実キーで要約が生成され `summary.md` に保存される。キー未設定・無効キーで
   落ちずに縮退する。
4. **オンライン文字起こしエンジン（OpenAI）**
   Whisper API への送信・`verbose_json`→既存スキーマ変換・25MB 超の時間分割＋オフセット
   結合を実装し、文字起こしワーカーのエンジン分岐に接続する。変換・分割の純粋部分に
   単体テスト。
   確認: 実録音で mic.json / system.json が生成され、Recordings の文字起こし表示・
   セグメントクリック（#54）がオンデバイス時と同様に動く。
5. **ドキュメント・文言の同期**
   README（機能・プライバシー記述）・LP（#75/#76 実装後なら該当文言）・`docs/CONTEXT.md` を
   新方針へ更新し、設定画面の警告文言を最終化する。
   確認: 「外部送信しない」と断言する記述が残っていない（既定では送信しない、に統一）。
6. **全体検証**
   `cargo build` / `cargo fmt --check` / `cargo clippy --all-targets -- -D warnings` /
   `cargo test` がすべて通る。録音→（各エンジンで）文字起こし→要約→表示の一連を確認する。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - 追加: `src/credentials.rs`（Keychain）、オンラインエンジン実装（`transcribe.rs` /
    要約モジュール配下、またはプロバイダ別サブモジュール）
  - 変更: `src/transcribe.rs`（エンジン分岐）、要約モジュール（#80。抽象前提の実装）、
    `src/config.rs`（エンジン選択・モデル上書き）、`ui/app-window.slint`(設定 UI)、
    `Cargo.toml`（`security-framework`）、README / LP / `docs/CONTEXT.md`
  - 前提: #79（モデル DL 共有ヘルパ）・#80（ローカル要約）と抽象の入れ方を揃える
- リスクと対策:
  - **機微データの外部送信**（本プランの本質的トレードオフ）: 既定 OFF・明示オプトイン・
    設定画面の警告・ドキュメント同期で「知らずに送信」を防ぐ。送信先は選択した 1 社のみ。
  - **API キーの漏えい**: Keychain 保存・マスク表示・ログ禁止（エラーはステータスと
    エラー種別のみログ。レスポンス本文・キーを含めない）。
  - **API 障害・レート制限**: 限定リトライ＋縮退（ジョブ失敗として記録し、手動再実行
    （#69/#81 のボタン）でやり直せる）。
  - **OpenAI の 25MB 上限**: 時間分割＋オフセット結合で対応。分割は決定的な純粋関数に
    してテストする。
  - **コスト**: ユーザー自身のキー・従量課金である旨を警告文に含める。
  - **各社 API の仕様変更**: プロバイダ実装を薄く分離し、リクエスト/レスポンスの
    解釈をテストで固定する。
  - **他 OS**: Keychain 未対応のためオンラインエンジンを選択不可にする（UI で無効化）。
    将来 Windows/Linux 対応時に資格情報ストアを追加する。

- オンライン要約の入力サイズ安全上限の具体値（実装時にトークン概算で決める）。
