# 録音ファイルをセッション単位のディレクトリにまとめる

- 作成日: 2026-06-28
- ステータス: ドラフト

## 概要

録音ファイルの保存先を `<保存ディレクトリ>/openshoki-{timestamp}-mic.mp3`（フラット）から
`<保存ディレクトリ>/<日時>/mic.mp3`（セッション単位のサブディレクトリ）へ変更する。
1 回の録音セッションが生む複数の成果物（マイク・将来のシステム音声・文字起こし結果）を
同じディレクトリにまとめ、セッションごとに見つけやすく・扱いやすくするのが狙い。

## 背景・前提（コンテキスト）

- CONTEXT.md の設計判断「マイク音声とシステム音声は別ファイルに保存」「1 回の録音セッションが
  音源ごとの複数ファイル（`-mic` / `-system`）を生む」を踏まえる。これらの成果物を**セッション
  ディレクトリにまとめる**のが今回の変更。さらに将来の文字起こし結果も同じ場所に置く前提。
- 現状の保存先組み立て:
  - `src/recorder.rs:72` — `recording_dir.join(format!("openshoki-{timestamp}-{MIC_SUFFIX}.mp3"))`。
    `Recorder::start(recording_dir, timestamp)` がファイルパスを自前で組み立てている。
  - `src/main.rs:168` 付近 — `timestamp = chrono::Local::now().format("%Y%m%d-%H%M%S")` を作り
    `Recorder::start(&dir, &timestamp)` を呼ぶ。`dir` は設定の `recording_dir`。
- 設定画面（`ui/app-window.slint`）で選ぶ「録音ファイルの保存先」は**親ディレクトリ**であり、
  その意味は変わらない。今回はこの下にセッションフォルダが作られるようになる。
- ディレクトリ名の日時形式は現行 timestamp と同じ `%Y%m%d-%H%M%S`（例: `20260628-143025`）を
  そのまま転用する（ユーザー確認済み）。

## 要件

- 録音セッションごとに `<保存ディレクトリ>/<日時>/` を作成し、マイク音声を `mic.mp3` として
  その中に保存する。`<日時>` は `%Y%m%d-%H%M%S`。
- 1 つの「保存ディレクトリ」設定の下に、セッションごとのフォルダが並ぶ構造にする。
- 将来 `system.mp3`（システム音声）や文字起こし結果を**同じセッションディレクトリ**に追加
  できる形にしておく（今回はマイクの `mic.mp3` のみ実装）。
- スコープ外:
  - システム音声録音・文字起こしの実装そのもの（別 issue。issue #5 等）。
  - 既存の旧レイアウトファイル（`openshoki-*-mic.mp3`）の移行・改名。新規録音から新レイアウト。
  - 設定画面の文言・UI 変更。

## 確定した論点

- **保存先レイアウト**: `<保存ディレクトリ>/<日時>/mic.mp3`。ファイル名は音源を表す固定名
  （`mic.mp3`）にし、日時はディレクトリ名が持つ。`openshoki-` 接頭辞・timestamp 接尾辞は
  ディレクトリに役割が移るためファイル名から外す。
- **日時ディレクトリ名の形式（ユーザー確認済み）**: `20260628-143025`（`%Y%m%d-%H%M%S`）。
  現行 timestamp をそのまま使えコード変更が最小、ソートもしやすい。
- **セッションディレクトリの責務**: 「保存先（親）＋日時 → セッションディレクトリ」の組み立ては
  呼び出し側（`main.rs`）で一度行い、`Recorder` には**セッションディレクトリ**を渡す。
  `Recorder` はその中に音源ファイル（`mic.mp3`）を書くだけにする。これにより、将来システム
  音声録音や文字起こしも同じセッションディレクトリを共有して書き込めるようになる
  （音源ごとに別々の親を組み直さない）。
- **ディレクトリ作成**: セッションディレクトリが無ければ作成する（現行の `create_dir_all` を
  対象パスに合わせて流用）。同一秒に 2 セッションは手動操作では起きないため衝突対策は設けない。

## 実装方針

責務を「パス組み立て（main）」と「書き込み（recorder）」で分ける:

1. `main.rs` の `toggle_recording` で、設定の保存先 `recording_dir` と timestamp から
   セッションディレクトリ `recording_dir.join(timestamp)` を組み立て、`Recorder::start` に渡す。
2. `Recorder::start` は受け取ったセッションディレクトリを `create_dir_all` し、その中に
   `mic.mp3` を作る。ファイル名は音源を表す定数にする。

`Recorder` が「親 + timestamp からファイル名を組む」責務を手放すことで、将来の音源追加時に
セッションディレクトリを使い回せる。

## 実装ステップ

1. **`Recorder` をセッションディレクトリ受け取りに変更**（`src/recorder.rs`）
   - `start(recording_dir: &Path, timestamp: &str)` を `start(session_dir: &Path)` に変更。
   - 定数 `MIC_SUFFIX`（`"mic"`）を、音源ファイル名 `MIC_FILENAME = "mic.mp3"` に置き換える。
   - 出力パスを `session_dir.join(MIC_FILENAME)` にし、`create_dir_all(session_dir)` で
     セッションディレクトリを作る。
   - 確認: `cargo build` が通る（呼び出し側を直すまではコンパイルエラーで検知できる）。

2. **呼び出し側でセッションディレクトリを組み立てる**（`src/main.rs`）
   - `toggle_recording`（`src/main.rs:159`）で、`let session_dir = dir.join(&timestamp);` を作り
     `Recorder::start(&session_dir)` を呼ぶ。timestamp 生成（`%Y%m%d-%H%M%S`）はそのまま。
   - 停止時の保存ログ（`"録音を保存した: {path}"`）が新パス（`.../20260628-143025/mic.mp3`）を
     表示することを確認する。
   - 確認: `cargo run` で録音→停止し、`<保存ディレクトリ>/<日時>/mic.mp3` が生成され再生できる。

3. **CONTEXT.md に保存レイアウトを反映**（`docs/CONTEXT.md`）
   - 「録音セッションは保存ディレクトリ配下に `<日時>` のサブディレクトリを作り、音源・
     文字起こし結果をその中にまとめる（`mic.mp3` / 将来 `system.mp3` / 文字起こし）」旨を
     設計判断として追記する。
   - 確認: 用語「録音セッション」と整合し、矛盾する旧記述が残っていない。

4. **整合確認**
   - 確認: `cargo build` / `cargo clippy`（CI 相当）が警告なく通る。未使用になった定数・引数が
     残っていない。

## 影響範囲・リスク

- 影響を受けるファイル/モジュール:
  - `src/recorder.rs`: `start` シグネチャ変更、ファイル名定数、`create_dir_all` 対象の変更。
  - `src/main.rs`: `toggle_recording` でセッションディレクトリを組み立て。
  - `docs/CONTEXT.md`: 保存レイアウトの設計判断を追記。
  - `ui/app-window.slint`: 変更なし。
- リスクと対策:
  - **既存の旧レイアウトファイルとの混在**: 旧 `openshoki-*-mic.mp3` は保存先直下に残るが、
    新規は `<日時>/` 配下になり混ざる見え方になる。移行はスコープ外と明記。実害は無い。
  - **セッションディレクトリ名の衝突**: 秒精度のため理論上は同秒 2 回で衝突しうるが、手動の
    開始操作では起きない。`create_dir_all` は既存ディレクトリでも成功するため致命的ではない。
  - **将来の音源追加との一貫性**: セッションディレクトリ組み立てを `main` 側に置くことで、
    system 音源や文字起こしが同じディレクトリを共有できる。今回その配線は作らないが、
    将来の拡張を妨げない形にする。
