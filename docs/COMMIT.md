# コミット規約

コミットするときに従うルール。`za:fix-issue` / `za:review` など、コミットを行うすべての
場面（人・AI ツールを問わず）でこの規約に従う。

## 言語

コミットメッセージは日本語で書く。コード識別子・コマンドは原語のまま。

## メッセージ形式

```
{種別}: {要約}

{本文：何を・なぜ変えたか。必要なら箇条書きで主な変更点}

{対応 issue があれば: 例) #42}
```

- **種別**: `feat` / `fix` / `refactor` / `docs` / `test` / `chore`（issue ラベルと対応）。
  - `feat` — 新機能
  - `fix` — バグ修正
  - `refactor` — 挙動を変えない改善
  - `docs` — ドキュメント
  - `test` — テストの追加・修正
  - `chore` — ビルド・設定・雑務
- **要約**: 日本語で簡潔に。命令形で「〜する」調に統一する。
- **本文**: 何を・なぜ変えたかを書く。複数点あれば箇条書きにする。自明な変更なら省いてよい。
- **issue 参照**: 対応する issue があれば本文に `#番号` を含める。
  「Closes #番号」はマージで自動クローズさせたい PR 側で使い、コミットには書かない。
- **粒度**: 1 コミット 1 論理変更。複数の関心事が混ざるなら分割する。

## 署名を付けない

コミットメッセージに **AI ツール（Claude など）の署名・生成表記を書かない**。具体的には、
次のようなトレーラー・文言を **一切付けない**:

- `Co-Authored-By: Claude ...`（および他の AI を指す Co-Authored-By）
- `🤖 Generated with ...` / `Generated with Claude Code` などの生成表記

人間の共同作業者を明示したい場合の `Co-Authored-By:` は通常どおり使ってよい。

## 例

```
feat: 設定画面を追加する

メニューから開ける設定画面を追加。表示・保存の基本動作を実装する。

#12
```

```
fix: 録音停止時のハングを防ぐ

送信側のクローズを poison 耐性にし、writer スレッドの recv が終わらず
join がハングするのを防ぐ。

#5
```
